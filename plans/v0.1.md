# pinakes v0.1 — implementation plan

**Status:** preliminary — under adversarial review · **Date:** 20260725 09:37
**Source of truth:** [`docs/DESIGN.md`](../docs/DESIGN.md) (pass 6). This plan sequences §8's v0.1
scope into ordered increments; where the two disagree, DESIGN.md wins and this plan has a bug.

## Goal

Ship the v0.1 vertical slice end to end: `pnk init` → `pnk sync` → `pnk search` → `pnk serve`,
with `pnk doctor`, `pnk install-hooks`, the golden-set eval harness, CI, and a 0.1.0 PyPI release.
Every increment below ends **green** (`uv run ruff check`, `uv run pyright`, `uv run pytest`) and
**committed on its own** — no batching, so any regression bisects to one increment.

## Ground rules (apply to every increment)

- **Worktree + branch per increment**, named `YYYYMMDD_HHMM-i<N>-<slug>` per the global convention.
- pyright **strict** from the first line; no `# type: ignore` without a stated reason.
- Tests accompany the increment that introduces the behaviour — never deferred to a "testing" phase.
- Docs rule (CLAUDE.md): any user-facing surface added in an increment updates `--help` text in the
  same commit. README's worked examples update when the command they show becomes real; README's
  status banner flips only in I15.
- The free-path invariant is enforced structurally: nothing in v0.1 imports an API client at all.
- `__version__` stays `0.0.0` until I15 cuts `0.1.0`.

## Decisions this plan makes (and why)

| Decision | Choice | Why |
|---|---|---|
| CLI framework | stdlib `argparse` subparsers | Zero dependency; the bootstrap stub already uses it; v0.1's flag surface is small. Revisit only if flags become unmanageable — that revisit is a MINOR change, not a rewrite |
| Manifest writing | Template rendering (jinja2), never TOML serialization | `tomllib` is read-only (verified: no `dumps`). §6.1 fixes `pinakes.toml.j2`, so jinja2 enters core deps — pure-Python, no weight. After `init`, **nothing ever rewrites the manifest**; it is user-owned like `docs/` |
| The one v0.1 template | `notes` | README's quickstart already names it; plainest possible blueprint |
| Template packaging | `src/pinakes/templates/notes/` via `importlib.resources` | Works from a wheel; no path assumptions |
| Embedding `revision` semantics | Enforced when set; `pnk init` leaves it unset with a comment; `pnk doctor` reports the resolved revision and suggests pinning | `init` cannot know the HF sha offline, and a manifest field silently written by machinery would violate "user-owned". Coherence (§4.4) always enforces provider+model+dim; revision additionally when present |
| Backend protocol | One `EmbeddingBackend` protocol: `embed(texts) -> ndarray`, `count_tokens(text) -> int`, `info() -> ModelInfo(provider, model, revision, dim, max_seq_length)`; one `Reranker` protocol: `score(query, passages) -> list[float]`, `info()` | Both `sentence-transformers` and fastembed satisfy it (fastembed exposes a HF `tokenizers.Tokenizer`; verified in-session). Chunking and retrieval test against fakes, so model downloads never enter unit tests |

## What this plan deliberately does NOT decide

PDF ingest (v0.2) · `pnk link` and cross-KB traversal (v0.3) · budget/ledger/`ask --deep` (v0.4) ·
`sqlite-vec` tier and template ecosystem (v0.5) · demo-KB prose content (written in I14, only its
*coverage contract* is specified here) · exact calibrated threshold values (produced by I14's
fitting, not chosen by a human).

## Increments

Dependency shape: I1→I2→I3 are the foundation; I4 (storage) and I5–I7 (sidecar/chunk/embed) fan out
from it; I8 (sync) joins I3–I7; I9 (retrieval) joins I4+I7; I10–I13 hang off I8/I9 independently;
I14 needs I8+I9+I10; I15 is last.

### I1 — Package skeleton, errors, CLI dispatch

`src/pinakes/`: `errors.py` (a `PinakesError` hierarchy — every user-facing failure derives from it
and carries a remedy string), `cli.py` rebuilt as argparse **subparsers** with one module-level
`run(args) -> int` per command, all still exiting 1 with the design-stage message. Exit-code
contract: 0 success, 1 operational failure, 2 usage error (argparse default).
**Tests:** help output lists every §8 command; each stub exits 1; unknown command exits 2.
**Exit criteria:** the current stub's tests are replaced, not deleted — behaviour parity proven.

### I2 — Identity: ULIDs and `pnk://` URIs

`ids.py`: mint/parse ULIDs (python-ulid), `KbId`/`DocId` NewTypes. `uri.py`: parse/format
`pnk://<kb-ulid>/<doc-ulid>`; `self` accepted on parse, **expansion requires the owning KB's id**
(API takes it explicitly — no ambient state); aliases rejected in URIs by construction.
**Tests:** round-trip, malformed rejection, `self` expansion, alias-in-URI rejection.

### I3 — Manifest model

`manifest.py`: frozen dataclasses mirroring §2.1 exactly (`[kb]`, `[sources]`, `[embedding]`,
`[chunking]`, `[retrieval]` incl. `[retrieval.confidence]` optional, `[rerank]`, `[budget]`,
`[[links.kb]]`), loaded with `tomllib`, validated with precise error messages naming the offending
key. Unknown keys are a **hard error** (a typo'd `finall_k` silently ignored is a wrong-behaviour
bug). `[budget]` is parsed and carried but consumed by nothing until v0.4 — validated so a KB
authored today doesn't break then. Also here: `find_kb_root(start=cwd)` — walk up to the nearest
`pinakes.toml` (git-style); every command that operates on a KB (`sync`, `search`, `doctor`,
`install-hooks`) uses it, accepts `--kb PATH` to override, and errors with a remedy when no
manifest is found.
**Tests:** golden valid manifest; one test per validation rule; unknown-key rejection; root
discovery from nested dirs, override, and not-a-KB error.

### I4 — Storage engine

`store.py`: schema DDL exactly per §3's table list, `schema_version = 1` in `meta`;
`open_rw(path)` (WAL, foreign keys on) and `open_ro(path)` (`file:…?mode=ro`, `busy_timeout`);
version mismatch raises with the `pnk sync --rebuild` instruction; FTS5 external-content table +
insert/update/delete triggers. Embedding vectors: float32 BLOB column; a loader returning one
contiguous `np.ndarray` plus row-aligned chunk ids (the §3.1 NumPy tier's substrate).
**Tests:** DDL applies on 3.13's sqlite; triggers keep FTS in sync through update/delete; ro handle
cannot write; version gate fires; BLOB round-trips exactly.

### I5 — Sidecars

`sidecar.py`: read/validate/write `<file>.pnk.yaml` (yaml.safe_load only), skeleton generation
(id, title from filename, created, empty tags/links), link entries with alias→ULID and self→ULID
expansion **at write time** (consumes I2 + I3's `[[links.kb]]`), duplicate-ID scan across a set of
sidecars. No `content_hash` — per §2.2 change detection is index-only.
**Policy:** v0.1 *creates* sidecars and *moves* them on rename (§6.4) but never rewrites an
existing sidecar's content — so pyyaml's comment-stripping on dump is moot until v0.3's `pnk link`
edits sidecars in place (which may adopt a comment-preserving writer then).
**Tests:** round-trip preserving unknown user keys (sidecars are user-editable; a rewrite that
drops their extra fields destroys data); expansion cases; duplicate detection.

### I6 — Structural chunking

`chunk.py`: Markdown chunker (split on heading boundaries, then paragraphs; heading-path recorded),
plain-text/code chunker (blank-line blocks; for code, no syntax parsing in v0.1 — stated
limitation), `max_tokens` enforcement via a `TokenCounter` protocol with overlap, oversize blocks
**split, never trimmed** (§4.6); validation of manifest `max_tokens` against
`max_seq_length - special_tokens` is a hard error.
**Tests:** fake counter (token = word) makes everything deterministic: heading paths, spans,
overlap arithmetic, the never-trim guarantee (every source char lands in ≥1 chunk).

### I7 — Embedding backends and reranker

`embed.py`: the two protocols from the decisions table; `load_backend(manifest)` dispatching on
`provider` through a **module-level registry dict** (open, not an enum: manifest validation accepts
any provider string; an unknown one fails at load time listing the registered providers — and tests
register a `fake` provider in that dict, which is what lets the quickstart acceptance test drive the
real CLI without model weights) with **lazy imports** — a core-only install raises `BackendMissingError` naming the
exact extra (§4.5); dim mismatch between manifest and model is a hard error. `st_backend.py`
(sentence-transformers + `CrossEncoder`) and `fe_backend.py` (fastembed `TextEmbedding` +
`TextCrossEncoder`). `max_seq_length` is not public fastembed API: `fe_backend` derives it from the
loaded HF tokenizer's truncation config; `st_backend` reads `model.max_seq_length`; both canary
tests assert the derived value is a sane positive int matching the model card (512 for the v0.1
defaults). Model resolution honours `HF_HOME` — for fastembed by passing an explicit cache dir under it,
since fastembed's own default is `$TMPDIR/fastembed_cache` (§4.5, verified upstream); `--offline` is a flag on every command that may load models
(`sync`, `search`, `serve`, `doctor`), mapped to the libraries' offline modes, failing fast with a
remedy when weights are absent.
**Tests:** unit tests use fakes only. One `@pytest.mark.model` integration test per backend
(embed + rerank a canary sentence, assert dim and score ordering) — skipped locally unless weights
are cached, always run in CI where I15's `HF_HOME` cache holds `[light]` weights.

### I8a — Sync pairing core (pure)

`pairing.py`: the §6.4 two-phase algorithm as a **pure function**:
`pair(before: IndexSnapshot, after: WalkSnapshot) -> list[Action]` — no I/O, no SQLite, no
filesystem. `IndexSnapshot` = the `documents` rows (id, path, content_hash, sidecar_hash, state);
`WalkSnapshot` = every source file's path+hash plus every sidecar's path, id and content hash.
Actions: `Skip`, `Reembed(id)`, `RefreshMetadata(id)`, `Rename(id, old, new)`,
`AdoptSidecar(id, path)`, `Mint(path)`, `SoftDelete(id)`, `AmbiguousDuplicate(...)`,
`DuplicateIdError(...)` — the §6.4 table row-for-row plus its three stated consequences:
soft delete removes chunks/embeddings, sidecar-only edits emit `RefreshMetadata`, and in
rename+edit the sidecar adoption wins over deletion (no `SoftDelete` for an adopted ID; the
sidecar-didn't-travel case is reported).
**Tests:** table-driven, one case per §6.4 row plus the compound cases (rename+edit in one sync;
duplicate content where one candidate has the old-ID sidecar; N-way ambiguity) — this is the
highest-risk logic in v0.1 and gets the densest test file.

### I8b — `pnk sync`

`sync.py` + `lock.py`. Walk sources per manifest include/exclude — `*.pnk.yaml` is
**categorically excluded** from the document set regardless of include patterns (an include of
`**/*.yaml` must never ingest sidecars as documents); hash; feed I8a; execute actions —
each document in its own transaction, parse/embed failures recorded in `failures`, run continues,
exit non-zero listing them (§6.4). Executing `SoftDelete` removes the document's **chunks and
embeddings** (and FTS rows via triggers) so a deleted document can never be retrieved; the
`documents` row stays (`state = deleted`) because it is the identity §6.4's pairing needs.
Sidecar-only edits refresh `documents.metadata` and `links` without re-embedding, tracked via
`documents.sidecar_hash` — semantics and schema are canonical in §6.4/§3 (design pass 7), the plan
just implements them. Lock per §6.5: pid/host/start-time record; live-holder → exit 0
quiet; dead-pid same host → reclaim + warn; other host → refuse; `--force-unlock`.
`--rebuild`: build `index.db.new`, `wal_checkpoint(TRUNCATE)`, close, rename; `ledger.jsonl`
untouched (create nothing — the ledger file itself is v0.4's; rebuild must simply not delete
files it doesn't own). `--quiet` suppresses progress output for hook/cron use (errors still print). `--sidecars-only
[--stage]`: mint+write sidecars for new docs; with
`--stage`, only for docs staged in git, then `git add` the sidecars (the §6.3 pre-commit mode);
outside a git repo `--stage` errors.
**Tests:** end-to-end temp-KB syncs with a fake backend; every §6.4 action observable in the index;
failure isolation (one poisoned file, N−1 indexed, exit ≠ 0); lock matrix (live/dead/other-host,
monkeypatched liveness); rebuild leaves a stranger file in `.pinakes/` alone and swaps atomically
(no `-wal` survivor).

### I9 — Retrieval

`search.py`: the §4.1 pipeline. Metadata filter → SQL WHERE (tags via sidecar-derived
`documents.metadata`, path prefix, source_type); FTS5 BM25 with **query escaping** (user text is
not FTS5 syntax — quote it); NumPy cosine over the I4 loader's array; RRF (k=60) →
`fusion_top_k`; reranker (when `rerank = "local"`) → `final_k`; result objects carry passage text,
doc id, path, heading path, span, and scores. Coherence gate (§4.4): provider/model/dim (+revision
when set) checked against `meta` before any query; mismatch refuses with the rebuild instruction.
Confidence: reranker scores → thresholds **only when** `[retrieval.confidence]` present *and*
`fitted_for` matches the active reranker model@revision; else `unknown` (§4.2). Term-coverage
tiebreak only.
**Tests:** deterministic fake vectors make ranking assertions exact; FTS injection strings; RRF
golden values; rerank=none path; confidence `unknown` on absent block, on `fitted_for` mismatch,
and thresholds on a fake scorer; coherence refusal.

### I10 — `pnk init` + the `notes` template + `pnk search` CLI

Template `src/pinakes/templates/notes/`: `template.toml` (`notes@1.0`), `pinakes.toml.j2`,
`README.md`, `eval/questions.yaml` (starter golden set for KBs stamped from it). `pnk init NAME
--template notes`: refuse non-empty target; mint KB ULID; render manifest; create `docs/`,
`.gitignore` (`.pinakes/`). `pnk search QUERY [--kb PATH] [--tag T]... [--path-prefix P] [--source-type T]
[--created-after D] [--created-before D] [-k N] [--json]` — the §4.1 filter set (tags, path, date,
source_type) in full: human output = ranked cited passages + confidence line; low confidence appends the §4.2
escalation note — worded as *"low confidence — retrieval-only result; `pnk ask --deep` (planned,
v0.4) will offer paid synthesis"* so the CLI never advertises a command that doesn't exist as if it
did.
**Tests:** init in temp dir → manifest parses via I3, ULID valid, re-init refuses; search
end-to-end against a fixture KB with fake backend; `--json` schema stable; help-text snapshot.

### I11 — `pnk doctor`

Checks, each `ok | warn | fail` with a remedy string: sqlite version/FTS5/`enable_load_extension`
probe (§3.1); backend importable (which extra if not); model + reranker weights present under `HF_HOME`
(true for both backends by construction — §4.5); index coherence incl. `fitted_for`; orphaned sidecars; duplicate IDs; dangling
intra-KB links (cross-KB targets reported as `unchecked` — traversal is v0.3); hook status
(present/absent/foreign); held sync lock + age; chunk count vs 50k advisory (§3.1); git-repo
status. `--prune` deletes orphaned sidecars only after printing the list (§6.4). Exit: 0 all-ok,
1 any fail, 0-with-output on warns.
**Tests:** one fixture per check in both states; prune prints-then-deletes; never touches
non-orphaned sidecars.

### I12 — `pnk install-hooks`

Writes the §6.3 three hooks. The scripts invoke `pnk` from `PATH` and exit 0 with a one-line
warning if it is not found — a hook that hard-fails every commit because a venv wasn't activated
would train users to `--no-verify` permanently. Existing user hook files: **refuse and print the lines to add** —
silently appending to or overwriting a user's hook is a trust violation; idempotent when the hook
is already ours (marker comment). `pnk doctor`'s hook check recognises ours/foreign/absent.
**Tests:** in a temp git repo — install, re-install (idempotent), foreign-hook refusal; a real
commit fires pre-commit and the sidecar lands in the same commit; post-commit syncs the index.

### I13 — `pnk serve` (MCP)

`serve.py` with `FastMCP` (verified import, mcp 1.28.1): tools `pinakes_search`, `pinakes_get`,
`pinakes_list_kbs`, each with a `kb` argument (the KB's `[kb].name` or its ULID, default = first
configured KB). `pinakes_get` returns the document's metadata (id, path, title, tags) plus its
source text from `docs/`, inside the same delimited evidence framing as search results;
`pinakes_list_kbs` returns name, ULID and document count per served KB. `pinakes_search` takes
the same filter set as the CLI (tags, path prefix, source_type, created range) — one filter
vocabulary, two surfaces.
Serves **only** KBs named on its command line (`pnk serve PATH...`); no tool argument accepts a
filesystem path; `pinakes_get` resolves doc ULIDs through the index only (§4.7). Read-only index
handles; per-request `stat()` staleness check → reopen (§6.5). Passages returned inside a
delimited evidence field (§4.7).
**Tests:** in-process MCP client session: tool listing, search/get round-trip, unknown-kb error,
path-shaped `kb` arg rejected, index swap mid-session picked up on next request.

### I14 — Demo KB, golden set, eval harness, calibration

`tests/demo-kb/`: synthetic corpus per §7 — ~30 Markdown docs written for the purpose, committed
with sidecars; its manifest **pins model revisions** (we control this KB, and the pin makes the CI
cache key stable). ≥40 questions in `eval/questions.yaml` spanning lexical-only, paraphrase-only,
filter-dependent, multi-hop, and **no-answer** cases. Multi-hop questions are scoreable without an
agent: each ships its scripted hop sequence (query per hop, expected doc to `get` between hops);
the harness executes the script and scores recall/MRR on the final hop — testing that the corpus
*supports* the §4.3 loop, not simulating an agent's judgement. `eval.py` (module + `python -m
pinakes.eval`): recall@k, MRR, rerank precision, false-abstain, false-confidence; JSON report;
`--baseline` compare with per-metric tolerance for CI. `calibrate.py`: fits
`low_below`/`high_above` on the golden set, emits the `[retrieval.confidence]` block +
`fitted_for`; the fitted values are committed into the **demo KB's manifest only**. The `notes`
template ships the block **commented out** with a pointer to calibration: thresholds fitted on the
demo corpus were not fitted on the user's corpus, and committing them to the template would assert
a calibration that never happened — `confidence: unknown` is the design's honest default (§4.2),
and the template's starter golden set exists so users can calibrate their own KB.
Uses `[light]` models (CI-cached); this is where CLAUDE.md's "golden-set eval justifies retrieval
changes" rule becomes enforceable.
**Exit criteria:** eval runs green in CI; calibrated thresholds committed; baseline JSON checked in.

### I15 — CI, packaging, 0.1.0

`.github/workflows/ci.yml`: uv-managed 3.13; `[light]` + dev deps; ruff, pyright, pytest (model
marks included), eval-vs-baseline gate; `HF_HOME` cached keyed on the demo KB's model ids+revisions
(§4.5). Release: `uv build`; wheel smoke test (`uvx --from dist/... pnk --version` and `pnk init`
in a temp dir — proves template packaging); README status banner flipped, quickstart verified
against the built wheel **by a scripted acceptance test, not by reading**; CHANGELOG 0.1.0 cut
(MINOR per the global release rule); tag `v0.1.0`; PyPI trusted publishing — **manual prerequisite:** the PyPI project and its
trusted-publisher binding to this repo must be configured by the user in the PyPI UI before the
release workflow can succeed; the plan flags this as a human gate, not automatable.
**Exit criteria:** a fresh `uv add "pinakes[light]"` from PyPI reproduces the README quickstart.

## Verification of the whole (not just the parts)

- The README quickstart is an executable acceptance test from I10 onward (`tests/test_quickstart.py`
  drives the real CLI in a temp dir with the fake backend; I15 runs it against the wheel with real
  `[light]` models).
- §8's v0.1 sentence is the checklist: at I15, every item in it maps to a shipped increment — walk
  the list explicitly in the release commit message.
- Invariants spot-checked in CI: no paid-API import anywhere (`grep` gate for `anthropic`/`openai`
  in `src/`), `.pinakes/` never committed (gitignore test), MCP tools all `pinakes_`-prefixed.

## Risks specific to this sequencing

| Risk | Mitigation |
|---|---|
| I8a's pairing table is subtly wrong and everything downstream builds on it | It's pure and lands early with the densest tests; §6.4's table is transcribed row-for-row into test names so a missing row is visible |
| Fake-backend tests pass, real models behave differently | The `@pytest.mark.model` canaries (I7) and the real-model eval (I14) both run in CI; only unit tests use fakes |
| `notes` template golden set too weak to calibrate on | I14 calibrates on the demo KB (≥40 questions); the template's starter set is seed material, and `confidence: unknown` is the honest fallback the design already specifies |
| jinja2/argparse decisions prove wrong mid-build | Both are contained: one renderer callsite, one CLI module; swapping either is a single-increment change |
