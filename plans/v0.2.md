## Goal

A PDF dropped into `docs/` is indexed, chunked, retrievable and citable by page — and the quality of
the text that made it in is **measured, not assumed**. DESIGN §9 calls PDF extraction *"the most
likely source of silent quality loss"*; the release exists to make that loss visible before it
reaches a user's answers.

v0.2 ships **two** extractors: a free, local, offline default (`pypdfium2`) and an **opt-in paid
Claude-vision extractor** that puts scanned PDFs in scope for the first time. Because a paid path
exists, v0.2 also ships **the whole budget machinery**: §5 says the budget system ships in the same
release as the first thing that can spend, "which is the honest ordering", and that first thing is
now the extractor rather than `pnk ask --deep`. Not scope creep — the design's own rule applied to
the user's decision. Every increment ends **green** (`./check.sh`, equivalently `make check`) and
**committed on its own**, so any regression bisects to one increment.

**Checked dead end — do not re-litigate.** Claude's **citations API** was investigated as a source
of exact character offsets and ruled out. Verified in the Anthropic API reference: a PDF `document`
block returns **`page_location`** (`start_page_number` / `end_page_number`, 1-indexed) —
**`char_location` is returned only for plain-text documents**. Citations are also a paid, query-time
call and are **incompatible with `output_config.format`** (400), the mechanism I7b uses to validate
extraction. So they cannot supply the offsets, cannot be free, and cannot coexist with the
extractor. Decision 4 stands.

**Checked and declined — server-side refusal fallbacks.** The Anthropic guidance is to ship
`claude-opus-5` code with the `fallbacks` parameter on by default (`fallbacks: "default"` under the
`server-side-fallback-2026-07-01` beta), because Opus 5's safety classifiers can decline a request
and a fallback silently rescues it. **v0.2 declines it, deliberately**: a rescued request is served
by a *different model*, and the extraction fingerprint (I7b) hashes the model id. A fallback would
therefore write text produced by one model into a cache entry claiming another — precisely the
silent-provenance failure the fingerprint exists to prevent, and undetectable afterwards. A refusal
here is a page failure with a recorded reason, on a synthetic corpus, which is a survivable outcome;
mislabelled cached text is not. Revisit only if the fingerprint learns to record the model that
actually answered, per page.

## Ground rules (apply to every increment)

- **The gate is an artifact, not a list of commands** (rule 1): `./check.sh` / `make check` passes
  immediately before `git commit`, and every new gate is **added to that script**, never described
  in prose. Two v0.1 commits landed red because the gate was a shell pipeline. New gates and owners:
  extras-not-core (I1), corpus-regenerates (I2), `pdf-eval` baseline (I3b), price-table
  well-formedness (I6a), paid-path allowlist (I7a).
- **A gate that cannot run must say so and still be a gate.** `pdf-eval` and the corpus's scanned
  stratum need `pinakes[pdf]`; gate 4 of the allowlist needs `pinakes[claude]`. Each **skips with a
  printed reason** when its half of the environment is absent (`pdf-eval: skipped — pinakes[pdf]
  not installed`), never silently, and a test asserts the printed reason — a skip nobody can see is
  the vacuous-metric failure (rule 3) wearing a different hat. CI runs the legs that make each gate
  meaningful.
- **Worktree + branch per increment**, `YYYYMMDD_HHMM-i<N>-<slug>` per CLAUDE.md.
- **No inline type suppressions at all** (rule 7). Both that existed in v0.1 hid real defects; the
  Anthropic SDK's response unions are the temptation here, so narrow with an explicit
  `block.type == "text"` check, never a cast.
- **Test-machinery rules, beside the algorithm rules** (rule 5): a fake must not derive its answer
  from the input under test, so **the fixture generator is not the extractor** and each fixture's
  ground truth is authored from its *spec*; a stand-in must be adversarial in the dimension it
  stands in for, so the registered `fake` extractor returns deliberately ugly text (double spaces, a
  stray running head, a hyphen join) and the **recorded** paid-API fixtures include a refusal, a
  schema-invalid page, a truncated (`stop_reason == "max_tokens"`) page and a page that drops
  content; no `or` in an equality assertion; a skip condition must check **every half** of its
  environment claim.
- **Two markers, stated scope.** `pdf` marks tests needing `pinakes[pdf]`, and its predicate checks
  the extra imports **and** the fixture exists. `paid` marks **only** tests that make a real API
  call, and its predicate checks `anthropic` imports **and** a key is present **and**
  `PINAKES_ALLOW_SPEND=1` is set. The recorded-fixture suite is **unmarked**: it must run with
  `anthropic` absent, which is what proves the registry seam. `PINAKES_ALLOW_SPEND` is a **pytest
  condition only, never a product guard** — the product's opt-in is already explicit
  (`[extraction] backend`, `--extract=`, the accountant), and a second env-var gate would be a
  footgun a user sets once in a shell profile and forgets.
- **Test-environment configuration lands in I1** (rule 6): both markers and their multi-part
  predicates, `SOURCE_DATE_EPOCH` pinning for fixture generation, and a probe that **both**
  `pypdfium2` and `anthropic` import silently under `filterwarnings = ["error"]` — a warning at
  import turns every test in that leg red, and the `anthropic` leg is new in this release.
- **Retrospectives are an input, not only an output** (rule 10): re-read `docs/RETROSPECTIVES.md` at
  the *start* of each increment, and land findings and fixes as their **own commit** — v0.1 lost
  that in 5 of 15 increments, and bisectability depends on it.
- Docs rule (CLAUDE.md): a user-facing surface added in an increment updates `docs/DESIGN.md`, the
  README and `--help` **in the same commit**; every date carries `HH:MM`; the CHANGELOG
  `[Unreleased]` line lands with the code, and `[0.2.0]` is cut by I9.
- **CI never spends money.** No CI job holds an API key; the paid path is exercised end to end from
  committed recorded responses. Real-API runs are human-gated (rule 9), with date, model and cost
  recorded.
- **v0.2 must not move the demo KB's eval numbers.** If `make eval` shifts, that is a defect to
  explain, not a tuning opportunity (CLAUDE.md's retrieval rule).

## Prior art: PDFScout

[PDFScout](https://github.com/lucagattoni/PDFScout) (the user's own project, MIT) is a LangGraph
multi-agent PDF extractor on Claude's native PDF vision. I7b is written against it deliberately, and
says so in its module docstring.

**Borrowed.** (a) **The completeness audit against the PDF's own embedded text layer** — PDFScout's
`coverage_node` compares significant words (alphabetic, ≥5 chars, NFKC-folded, order-free) from the
native layer against the model's per-page output and re-extracts pages that dropped or duplicated
content. Here it is *free*, because pypdfium2 already produced that layer in I3b, so it is the paid
path's quality gate at zero marginal cost. It brings PDFScout's own caveat too, which becomes a risk
row: a scanned page has **no usable native layer**, so the audit is blind on exactly the pages the
paid path exists for, and the corpus's hand-authored ground truth is what covers those. (b)
**Per-page schema validation with bounded retries** (≤3), so a malformed page is re-asked rather
than silently truncating the document. (c) **Provider-side prompt caching** — PDFScout reports pages
2–N at ~10% of input cost, which is a *hit-path* figure and not a reservation basis (I6a). (d)
**Local pre-checks before any API cost** — page count and encryption detection, offline.

**Rejected.** *LangGraph and the multi-agent graph* — pinakes has one extraction task, and a graph
framework is exactly the "second, worse agent framework" §9 names as a risk. *The classifier and
hierarchy agents* — they produce a document tree; pinakes needs linear text with page spans, and a
hierarchy would be a second structure with no consumer (v0.1's I6 is the record of what an unused
structured column costs). *SQLite checkpoint/resume* — resume uses per-page staging files inside the
extraction cache instead (I7c), rather than a second durability surface beside the cache and
per-document transactions that already exist. *Per-page parallel fan-out, in v0.2* — the hard cap is
a **running** reservation total (§5) and concurrent calls can breach it between reservation and
reconciliation; parallelism lands in v0.3 once the accountant has a ledger to prove itself against.

## What this plan deliberately does NOT decide

- **Table structure recovery.** The table stratum measures whether a table's text survives in
  readable order with label/value adjacency intact — not whether a grid is reconstructed as a grid.
- **PDF outlines/bookmarks as a `heading_path` substitute.** Pages are the unit v0.2 ships.
- **The Files API** (`files-api-2025-04-14`) instead of base64 document blocks. It uploads once and
  references a `file_id` across requests, but needs the beta header on **both** the upload and the
  message call plus an upload lifecycle to clean up. **Default: base64 + prompt caching** — same
  cost profile, no extra lifecycle. Revisit if a corpus routinely re-extracts the same document.
- **Figures, embedded images, captioning** beyond what the paid extractor's page output already
  says; Office, HTML, email, chat (§1 rules them out); any change to chunking parameters, fusion,
  reranking or the confidence signal; `pnk link` and cross-KB traversal (v0.3); `sqlite-vec` (v0.5).
- **`pnk ask --deep`** — still v0.4; v0.2 ships the budget machinery it will use, not the loop.
  **Default:** the accountant's "operation" for v0.2 is one `pnk sync` invocation — which bounds a
  single invocation and nothing else, so the day and month windows (I6a) are what bound a *sequence*
  of them.

### I1 — Extras, the extractor seam, and an honest core-only failure

`pyproject.toml` gains `pdf = ["pypdfium2>=5.12"]` and `claude = ["anthropic>=0.116"]` under
`[project.optional-dependencies]`. Both floors verified against PyPI **20260727 16:00**: pypdfium2
5.12.1 is the latest release (uploaded 20260717) and 5.x is a major jump from the 4.x series that
touches the character-level text API I3b targets, so the floor is deliberately at 5.12 rather than
`>=5`; `anthropic` 0.116.0 exists (uploaded 20260702) and 0.120.0 is the latest (20260724), so the
floor admits the current SDK without pinning to it.

`src/pinakes/extract/` becomes a package: `__init__.py` holds an `Extractor` protocol
(`extract(path) -> RawPages`, `fingerprint() -> str`), the frozen `RawPages` / `Page` / `Block` /
`CharSpan` types, and an **open module-level registry keyed on backend name with lazy imports** —
the single best structural call of v0.1 (I7), and what lets the real CLI be driven end to end with
neither extra installed. Both backend names (`pypdfium2`, `claude-vision`) are **registered at I1**
with loaders that raise `ExtractionError("the pypdfium2 adapter lands in I3b")` /
`ExtractionError("the claude-vision extractor lands in I7b")`; manifest validation checks membership
in the registry's key set and **never imports**, so an unknown backend is rejected at I1 without
either extra being installable.

`errors.py` gains `ExtractorMissingError` (names the extra) and `ExtractionError`, both routed
through the existing `_rebuild` helper so they survive pickling (v0.1 I1/I4). `chunk.source_type`
maps `.pdf` → `"pdf"`. `sync._index_document` **routes on `source_type`** instead of unconditionally
calling `read_text(encoding="utf-8")`; a PDF today raises `UnicodeDecodeError` and is logged as an
opaque `index`-stage failure. The manifest gains `[extraction] backend = "pypdfium2"`. `pnk doctor`
gains a `pdf extractor` check: OK when importable, WARN naming the extra when `include` can match
`*.pdf`. Test-environment configuration per rule 6, listed in the ground rules. **Tests:** registry
dispatch and a monkeypatched import failure raising `ExtractorMissingError` naming `pinakes[pdf]`,
plus the I1 stub loaders raising `ExtractionError` naming their increment, no uninstall needed
(`tests/test_extract.py`); the extended `source_type` table (`tests/test_chunk.py`); a KB with one
PDF and no extractor recording a `failures` row at stage `extract`, indexing the other N−1
documents, exiting non-zero and printing the remedy **once** rather than per document
(`tests/test_sync.py`); an unknown `backend` rejected without importing anything
(`tests/test_manifest.py`); `tests/test_packaging.py::test_extractors_stay_extras` asserting neither
library appears in `[project.dependencies]`, so the `check.sh` gate has a test that owns it (rule 8
— v0.1's paid-API gate had no owner and never shipped). **Exit criteria (repo-verifiable):**
`./check.sh` green under `--extra light`, under `--extra light --extra pdf`, and under `--extra
light --extra pdf --extra claude`; a new `check.sh` gate fails if `pypdfium2` or `anthropic` appears
in `[project.dependencies]`; `pnk doctor` prints the new check in both install states.

### I2 — The synthetic hard-case PDF corpus and its generator

`tests/pdf-corpus/`: a committed generator, the committed PDFs it produces, and one hand-authored
`<name>.expected.txt` per fixture. **No real-world PDF is ever committed** (CLAUDE.md: the repo is
the engine). Ground truth comes from the generator's *spec*, never from extractor output — otherwise
the test asserts only that the extractor agrees with itself. Sized **per stratum, not in aggregate**
(rule 4 — v0.1 sized its golden set at ≥40 in aggregate and still ended with an 8-question no-answer
stratum it had to label a floor):

| Stratum | n | Must contain |
|---|---|---|
| two-column | 3 | reading order across a gutter; a caption straddling both columns; a left column ending mid-sentence |
| tables | 3 | a bordered grid; a borderless whitespace-aligned table; one with a spanning header cell |
| headers / footers | 3 | a repeating running head; page numbers; a footer present only on page 1 |
| ligatures & hyphenation | 3 | U+FB01/U+FB02; a soft hyphen; a word split across a line break **and** one across a page break |
| **scanned / image-only** | 3 | a page rastered from known glyph coordinates with **no text layer**: clean, skewed 2°, low-contrast. This is the stratum the paid path exists for |
| pathological | 2 | a text layer in invisible render mode; a truncated/corrupt-header file |
| baseline | 2 | plain single-column prose, one page and twelve pages |

Nineteen documents, ≥45 pages, **≤ 2 MB committed in total, of which the scanned stratum is ≤ 1.5
MB** — a stated number, asserted by a test, so a fixture cannot balloon unnoticed.

The generator writes raw content streams for the sixteen text-layer fixtures, no layout engine and
**no dependencies**: those fixtures are not documents, they are **text layers with known
coordinates** using the PDF base-14 fonts, and a layout engine would hide the variable under test
behind its own decisions.

**The scanned stratum is generated differently, and gated differently.** It rasters the *same*
coordinates as its text-layer twin, so its ground truth is identical to the twin's — which makes
free-vs-paid directly comparable on the same content. Producing that raster needs a renderer and an
image writer: `pypdfium2` (the `pdf` extra, already present) renders the twin's page to a bitmap,
and **Pillow** (new, in the dev dependency group only — never core, never an extra) applies the skew
and contrast transforms and writes the image-only PDF at 150 dpi, 8-bit grayscale, Flate-compressed.
JPEG is never used: JPEG encoders differ across builds, and lossless Flate keeps the pixels the
generator produced. Rendering is not extraction, so rule 5's "the generator is not the extractor"
holds — the ground truth still comes from the spec.

**Byte-identical regeneration is not achievable for rasters** and pretending otherwise would make
the gate CI-flaky on any pdfium or Pillow bump. So the gate splits: the sixteen text-layer fixtures
must regenerate **byte-identically**; the three scanned fixtures are checked by structure (no text
layer, expected page count, image geometry and colour mode) plus a **mean absolute per-pixel
difference ≤ 2/255** against the committed image. A mean, not a max: a resampling change at glyph
edges must not fail the build, a moved word must. A renderer bump that exceeds the tolerance is
handled by regenerating and committing the new rasters in a commit that says so.
**Tests:** `tests/test_pdf_corpus.py` — byte-identical regeneration of the text-layer strata (fixed
producer string, `CreationDate`/`ModDate` from `SOURCE_DATE_EPOCH`); the scanned stratum's
structural + tolerance check, `pdf`-marked and skipping with a printed reason when the extra or
Pillow is absent; every fixture has a ground truth and every ground truth a fixture; stratum counts
match the table, so the corpus cannot silently shrink; the committed byte budget holds.
**Exit criteria (repo-verifiable):** `make corpus` leaves no diff on the text-layer strata and no
tolerance breach on the scanned stratum, and that check is a gate in `check.sh` that skips the
scanned half with a printed reason when its dependencies are absent. **Not** an exit criterion: any
claim about extraction quality — nothing extracts yet.

### I3a — Extraction core, pure (rule 11: the pure half)

`extract/layout.py`, operating only on the I1 types — no PDF library, no filesystem:

- `blocks_from_chars(chars) -> list[Block]` — pdfium's text API is **character-level**, and turning
  a character stream into blocks is the single densest piece of logic in the extraction path. It
  lives here, pure and table-driven against hand-built character streams, rather than inside the I/O
  adapter where it would be reachable only through an end-to-end corpus score (rule 11).
- `reading_order(page)` — column detection by x-gap clustering, then top-to-bottom within a column.
- `strip_running_heads(pages)` — a line recurring in the same y-band on ≥ *T* of pages, digits
  normalised, is a running head. **The threshold ships with its denominator**: the result reports
  `suppressed N of M pages`, so a wrong *T* is visible instead of silently eating a real heading.
- `join_hyphenation(lines)` — join a trailing hyphen or U+00AD when the continuation starts
  lowercase; never join across a heading or a suppressed running head.
- `normalise(text)` — ligature expansion (U+FB00–U+FB06), NFC, an explicit whitespace policy.
- `assemble(pages) -> ExtractedText(text, page_spans)` — **offsets are emitted with the text, never
  accumulated afterwards** (v0.1 I6: spans from `match.start()` rather than a running total are
  exact by construction rather than by accounting).
- `LAYOUT_VERSION` — a hand-bumped constant hashed into **every** backend's fingerprint, because a
  change to reading order or hyphenation changes the extracted text as surely as a library upgrade
  does, and would otherwise be a silent cache hit.

**Tests:** `tests/test_extract_layout.py`, table-driven — one case per rule, plus the compound cases
a table cannot express: a two-column page continuing mid-sentence into the right column; a running
head that is a genuine heading on exactly one page; a hyphenated word split across a page break
where the next page opens with a running head. `blocks_from_chars` gets its own dense table:
characters out of reading order, a word split across two text runs, overlapping bounding boxes, a
zero-width character, and a page with no characters at all. Two property assertions over **every**
case: `"".join(text[s:e] for s, e in page_spans) == text`, and `page_spans` contiguously covers `[0,
len(text))`. **Exit criteria (repo-verifiable):** one named test per rule and per compound case;
both properties hold across all of them; an import-graph test asserts `layout.py` imports no PDF
library.

### I3b — The pypdfium2 adapter, the quality metrics, and the two fitted floors (rule 11: I/O)

`extract/pdfium.py` is a **thin reader**: open a file, guard its size against a stated limit, refuse
an encrypted or corrupt-header file with a named error, and emit `list[CharSpan]` per page for I3a's
`blocks_from_chars` to assemble. Everything that decides *what the text is* now lives in the pure
half; what remains here is I/O, and that is where review effort is budgeted (rule 11's corollary:
v0.1's pure half produced one finding and the I/O half four, all environmental).

Its option set is **pinned and hashed** into the fingerprint. Fingerprinting is a **per-backend
protocol method**, not one shared formula — a shared formula would hash `pypdfium2`'s version for a
backend that never loads it while omitting the model that actually produced the text (H4). This
backend returns `sha256(backend name, pypdfium2 version, pdfium build, option dict,
LAYOUT_VERSION)`, truncated; the paid backend's inputs are stated in I7b. The value is written to
`documents.extraction_fingerprint` (with `documents.extraction_backend`) at sync, and into the I4
cache key.

`extract/quality.py` scores an extraction against a ground truth. **Every rate ships with its
denominator as a co-metric** (rule 3 — v0.1's `false_abstain: 0.0` was vacuous and would have passed
a CI gate forever):

| Metric | Numerator | Denominator |
|---|---|---|
| `char_recall` | expected non-space characters found, in order | expected non-space characters |
| `order_fidelity` | LCS length over word sequences | expected word count |
| `junk_rate` | extracted words absent from the ground truth | extracted word count |
| `pair_adjacency` | asserted (label, value) pairs within *N* characters | asserted pairs |
| `word_coverage` | significant native-layer words present in the extraction | significant native-layer words |
| coverage | `documents_scored`, `pages_scored` | `documents_total`, `pages_total` |

`word_coverage` is the PDFScout completeness audit, defined here as a pure function of two strings
so it can be tested against hand-computed answers; I7c consumes it as the paid path's re-extraction
trigger, and a metric that can be wrong on a known input is not fit to gate anything.

**Both thresholds that later cost money are fitted here, on the I2 corpus, and recorded with their
provenance.** Neither is chosen by intuition, and neither is defined in the increment that spends
against it:

- **The `word_coverage` re-extraction floor** (consumed by I7c). Fitted as the 5th percentile of
  `word_coverage` over the six non-scanned strata, comparing pypdfium2's own extraction against the
  hand-authored ground truth, rounded down to two decimals. The scanned stratum is the **exempt
  control** — no native layer, `word_coverage` undefined, never scored as a pass. The fitted value
  and `fitted_on` (corpus revision + `YYYYMMDD HH:MM`) are committed in `baseline.json`. **Absent a
  fitted floor, the audit reports coverage and triggers no paid re-extraction at all** — the same
  fail-closed shape as v0.1's `confidence: unknown`, and the reason is identical: a threshold with
  no provenance is a number, not a measurement, and this one spends money.
- **The `text yield` floor** (consumed by I7b's free-path pre-check *and* I8's `pnk doctor` check).
  Non-whitespace characters per page: the three scanned fixtures are the positive control at zero,
  the twelve-page baseline the negative control. Defined here rather than in I8 because two
  increments consume it and neither may define it for the other.

`python -m pinakes.extract.quality tests/pdf-corpus` writes a JSON report; `--baseline` compares
**per stratum** with a tolerance, mirroring `eval.compare`; `make pdf-eval` wraps it and joins
`check.sh`, skipping with a printed reason when `pinakes[pdf]` or the corpus is absent (I1's exit
criterion is that the gate is green under `--extra light`). The scanned stratum's expected free-path
`char_recall` is **0.0** — a declared zero with its fixtures named, not a passing score. **Tests:**
`tests/test_extract_quality.py` — each metric on hand-built strings with hand-computed answers;
`documents_scored == documents_total` for every stratum; a planted regression (one fixture's
extraction truncated to its first page) **fails** the baseline comparison; both fitted floors are
present in `baseline.json` with a `fitted_on` timestamp, and the audit refuses to trigger a
re-extraction when the floor is absent. `tests/test_extract_pdfium.py` (`pdf`-marked) — the reader's
own contract: the corrupt-header fixture raises a named error rather than crashing, the size guard
fires at its stated limit, an encrypted file is refused before any parse, the invisible-render-mode
fixture yields the characters it actually contains, and a zero-page file is an error not an empty
success. `tests/test_check_script.py` — `pdf-eval` skips with its printed reason when the extra is
absent, and `check.sh` still exits 0. **Exit criteria (repo-verifiable):** `make pdf-eval` green
against a committed `tests/pdf-corpus/baseline.json`; the planted-regression test passes by failing
the comparison; every stratum's denominators are non-zero; both floors committed with values and
`fitted_on`.

### I4 — The extraction cache

`extract/cache.py`. One JSON per entry — `{schema, content_hash, backend, fingerprint, page_count,
page_spans, text}` — because a text/JSON pair introduces a half-written-pair corruption class that
need not exist. Written to a sibling temp and `os.replace`d. Invalidation is **by key, never by
mutation**: an edited PDF or a changed fingerprint simply misses.

```text
.pinakes/
├── index.db          ← disposable, rebuilt
├── ledger.jsonl      ← NEVER touched (§6.3)
└── cache/extract/
    ├── <content_hash>-<fingerprint>.json      ← a complete extraction
    └── partial/<content_hash>-<fingerprint>/  ← per-page staging, written only by I7c
```

Eviction: after a **fully successful** sync, entries whose `content_hash` matches no active document
are removed — never after a run that recorded failures, never during `--sidecars-only`, never during
`--rebuild` before the swap succeeds. `pnk sync --clear-cache` (named in §6.3, never implemented)
empties `cache/` only; `--rebuild` leaves it alone, which is the whole point of a cache.

**`--clear-cache` confirms before it destroys.** It prints the entry count and bytes it is about to
remove and requires a `y`; `--yes` skips the prompt for cron use. I7c extends the printed summary
with the euros those entries cost, read from the ledger, and amends CLAUDE.md's
"`.pinakes/` is disposable" invariant to except the paid extraction cache — the two halves are split
because the paid entries and the ledger reader do not exist until then, and a plan that pretends
otherwise is a plan with a forward reference in its code.

`pnk doctor` reports entry count, bytes, and `orphans / entries`.
**Tests:** `tests/test_extract_cache.py` — a second sync of an unchanged PDF calls the adapter
**zero** times (spy-counted); a changed document, a changed fingerprint and a truncated cache file
each miss rather than crash; two KBs holding the same PDF get two cache files. Plus
`tests/test_sync.py::test_clear_cache_preserves_the_ledger` and
`::test_clear_cache_without_yes_and_without_a_tty_aborts`.
**Exit criteria (repo-verifiable):** the zero-call assertion; the ledger-survives assertion;
`--clear-cache` and `--yes` in `pnk sync --help` and in §6.3's prose in the same commit.

### I5 — PDF chunking, page provenance, and the span invariant (`schema_version` 2)

`chunk_document(kind="pdf")` consumes the extraction's blocks, split at page boundaries so a chunk
never spans two pages without recording both. The existing `_fit` / `_atomise` machinery is reused
unchanged — and its guarantees are **re-asserted for the new path, not assumed**: the token limit,
never-trim, and the overlap-must-not-breach-`max_tokens` rule that v0.1's I6 found broken.
`store.py`: `chunks.page_start` / `page_end` (INTEGER, NULL for non-paged sources), `ChunkRow` and
`Chunk.as_row()` grown together (already coupled), `SCHEMA_VERSION = 2`. `heading_path` stays
**NULL** for PDFs — a PDF has pages, not headings, and stuffing `"p. 7"` into a free-text
filter/citation column is v0.1's I6 defect rewritten.

**The fingerprint is per document, not per index.** `documents` gains `extraction_backend` and
`extraction_fingerprint` (TEXT, NULL for non-extracted sources). A single `meta` key could not
describe a corpus where `pnk sync --extract=claude-vision` ran over some documents and the free path
over others — which the CLI explicitly allows — so it would either be wrong or refuse every query on
a perfectly coherent KB after any `--extract` run. §4.4's coherence gate therefore checks **each
document against its own recorded backend**: for every distinct `(backend, fingerprint)` pair among
active documents, re-derive that backend's current fingerprint and compare. Any mismatch **refuses
the whole query**, naming the affected documents and the count, with the same remedy shape as a
model mismatch — partial results from a half-stale index are the silent-garbage failure §4.4 exists
to prevent. When a recorded backend is not importable the check cannot run: `pnk doctor` WARNs and
queries proceed unmarked, because an extractor that is absent cannot have changed the extraction.
**Tests:** `tests/test_chunk_pdf.py` — **the span invariant over all 19 fixtures and every chunk**
(`chunk.text == extracted.text[char_start:char_end]`); every character of the extraction lands in ≥1
chunk (v0.1's never-drop guarantee, re-proved here); page numbers monotonic and within
`1..page_count`; a two-page chunk recording both; `heading_path is None` for every PDF chunk.
`tests/test_store.py` — schema version 2, and a version-1 index refusing to open naming `pnk sync
--rebuild`. `tests/test_search.py::test_a_changed_extraction_fingerprint_refuses_the_query` — a
mixed-backend index where every document matches its own backend queries fine; mutating one
document's stored fingerprint refuses with the remedy and names that document; an absent backend
WARNs in doctor and does not refuse. **Exit criteria (repo-verifiable):** the invariant holds
corpus-wide; `SCHEMA_VERSION == 2`; a v0.1 index raises `IndexSchemaError` with the rebuild remedy;
the mixed-corpus coherence test passes; the CHANGELOG entry states the forced rebuild in the same
commit.

### I6a — Budget core, pure (rule 11: the pure half of the money machinery)

`src/pinakes/budget/`, with **no I/O and no `anthropic` import**. `prices.toml` ships in the wheel
like the templates, carrying `as_of` as `YYYYMMDD HH:MM`, per-model `input_per_mtok_usd` /
`output_per_mtok_usd`, the cache-write (1.25×) and cache-read (0.10×) multipliers, and — because the
manifest prices in EUR and the vendor in USD — a `usd_per_eur` rate carrying the **same** `as_of`.
Seeded from the current table: `claude-opus-5` at $5.00 / $25.00 per MTok.

**`estimate.py` estimates over *requests*, not pages.** This is the difference between a reservation
that bounds a run and one that is short by an order of magnitude. Provider-side prompt caching is
only meaningful if **each page is its own request that re-sends the whole document** as a cached
prefix — so per-request input is roughly *whole-document* tokens, not per-page tokens, and an
N-page document costs `N × doc_tokens` of input at varying multipliers, not `N × page_tokens`. At
200 pages those differ by about an order of magnitude, which turns §5's "slight over-reservation"
into systematic under-reservation.

So: **worst case per request = `doc_tokens × 1.25 × input_price + max_tokens × output_price`.** The
1.25 bounds both the cache-write premium on the first request and a cold miss on any later one; the
0.10× cache-read multiplier is a *hit-path* fact used to explain the reconciled saving, never to
size a reservation. The output bound is `max_tokens` — the request's hard output ceiling, which on
`claude-opus-5` caps thinking and response text *together*, so it is the correct and only safe
bound. Reconciliation folds the response's true `usage`
(`input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens`) back in
and returns the saving to the running total.

The per-page token constant is **measured**, not guessed, with `measured_on` recorded beside it.
Until that measurement (human-gated, I7b) it uses a documented conservative ceiling of **6,000 input
tokens per PDF page**, derived from the vendor's own documented high-resolution page budget (up to
~4,784 visual tokens for a rendered page, plus that page's text) — a per-page number applied to the
*actual* page count, never the API's 600-page maximum. The estimate ships its denominator as
`pages_estimated N of M`.

`reserve.py` is the §5 accountant, and it is pure: `reserve(estimate, caps, spent) -> Decision`,
where `spent` is a `WindowTotals(operation, day, month)` the caller supplies. **Before every call it
checks all three ceilings** — `per_operation_eur`, the new `daily_eur`, and `monthly_eur` — and if
any of `spent.X + reserved` exceeds its cap the call is **never made**. The refusal names which
window blocked it and by how much. One operation being one `pnk sync` bounds a single invocation
only; the day and month windows are what stop a sequence of invocations, which is the failure mode
a hook-driven KB actually has.

`window.py` aggregates an in-memory list of ledger records by day/month in `[budget] timezone`;
reading the file is I6b's job, which is what keeps this half pure. `[budget]` gains
`max_price_age_days` (default 30) — an estimate against older prices is refused, not silently wrong
— and `daily_eur` (default 1.00, between the 0.05 per-operation cap and the 5.00 monthly one: a
burst limiter, where monthly is the real ceiling).

**The default `per_operation_eur` refuses almost every paid extraction, and that is correct.** At
$25/MTok output, a single page reserved at `max_tokens = 8000` is already ≈ €0.18, well past the
€0.05 default that was sized for one `pnk ask --deep` question. The refusal prints the computed
estimate and the exact manifest edit required. Raising the cap is the explicit opt-in; the plan does
not lower `max_tokens` to sneak under a default that was never meant to cover a 200-page document.
**Tests:** `tests/test_budget_core.py`, table-driven — the exact cap boundary for **each** of the
three windows (`spent + reserved == cap` proceeds; one cent more does not), and a case where the
operation cap passes but the month's does not; `test_reservation_bounds_a_cold_cache_usage_table` —
hand-written `usage` records covering a cold-cache first request, a cache hit, and a cache miss
mid-run, asserting the reservation is never below the reconciled actual; confirm threshold and hard
cap staying independent, so confirming at the cap value is reachable (DESIGN pass 3's finding);
window boundaries across a DST transition in a non-UTC timezone; a stale `as_of` refusing to
estimate and naming the remedy; a malformed `prices.toml` as a startup error, not a silent zero.
**Exit criteria (repo-verifiable):** the boundary tests for all three windows; an import-graph test
asserting `budget/` imports neither `anthropic` nor anything under `extract/`; a `check.sh` gate
parsing `prices.toml` and failing if `as_of` is missing or unparseable. **Deliberately not a CI
gate:** price *staleness* — a wall-clock gate fails the build on a quiet weekend with no code
change, so staleness is a `pnk doctor` WARN and a runtime refusal, where it protects a user instead.

### I6b — Budget I/O: the ledger, the prompt, `pnk budget`, and hooks that cannot spend

`budget/ledger.py` appends to `.pinakes/ledger.jsonl`; each line is a single sub-4KB `O_APPEND`
write, atomic on POSIX (§5). **The ledger stores no query text and no document content** —
timestamp, operation id, operation kind, model, token counts, cost, KB id, nothing more — and a test
asserts it by running a paid extraction from a recorded fixture whose page text contains a unique
sentinel and grepping the whole ledger for it.

**Cost is recorded in USD with its conversion provenance, never as a bare number.** Each line
carries `cost_usd`, the `usd_per_eur` rate used, and the price table's `as_of`. EUR is computed at
read time. A ledger line that says only `cost: 0.043` is unreadable a month later — nobody can tell
which currency it is or which rate produced it — and the rate is exactly the number that drifts.
`pnk budget` shows, per window, which rate and which `as_of` its totals were computed with, and
flags a window that spans more than one rate.

Two lines per call keyed by one operation ULID: a **reservation** written *before* the call and a
**reconciliation** *after*. That is the durability answer (rule 12) — a crash between the call and
the ledger write would otherwise lose spend history permanently, the one thing in `.pinakes/` that
cannot be recomputed — and a reservation with no reconciliation is reported as `unknown outcome`,
not dropped and not counted as zero. Reading the ledger into I6a's `WindowTotals` is this module's
job; the wiring is tested, not assumed.

`confirm_above_eur` prompts on a TTY; **with no TTY and no explicit `--yes` the run aborts**, never
proceeds silently, and `--yes` (required for cron) says in `--help` what it authorises: it answers
the confirmation prompt and `--clear-cache`'s confirmation, and **raises no cap**.

**Hooks and CI cannot spend.** DESIGN §6.3 makes `pnk sync` machine-driven — `pre-commit`,
`post-commit`, `post-merge`, and the workflow `pnk init --ci` writes. All four are non-interactive,
so on a KB configured for `claude-vision` the no-TTY abort above would kill hook-driven freshness on
every single commit, and a `--yes` in a hook would spend afresh on every commit with a fresh
per-operation allowance each time. Resolution: `pnk install-hooks` and `pnk init --ci` write
`pnk sync --extract=pypdfium2` **explicitly**, forcing the free backend regardless of the manifest,
print one line saying so at write time, and carry the same line as a comment in the generated hook.
A machine-driven sync therefore indexes a scanned PDF's (empty) free extraction and records it
honestly; paid extraction stays a deliberate human invocation. `pnk doctor` reports the combination
(paid backend configured, hooks installed and forcing the free one) so the split is visible rather
than surprising. `make budget` wraps `pnk budget` and is created **here**, by this increment — I9
only documents it.

`pnk budget` shows spend by day/month/operation with `reservations N, reconciled M, unknown K`;
`pnk doctor` gains a price-table check: OK, or WARN past `max_price_age_days` naming the file.
**Tests:** `tests/test_ledger.py` — the sentinel test; a process killed between reservation and
reconciliation leaving a readable ledger and an `unknown outcome` row; concurrent appends from two
processes interleaving no record; `--rebuild` and `--clear-cache` both leaving the ledger
byte-identical; every line carries `cost_usd`, `usd_per_eur` and `as_of`.
`tests/test_cli_budget.py` — `pnk budget` on an empty ledger printing zeros rather than a traceback;
totals on a mixed ledger matching a hand-computed fixture, including a window spanning two
`usd_per_eur` rates; no-TTY without `--yes` exiting non-zero with a remedy; **a KB whose ledger
already holds €4.99 of a €5.00 month refuses the next call even though the operation cap is
untouched** — the seam between I6a's arithmetic and I6b's ledger read, proved rather than assumed.
`tests/test_hooks.py` — all three hooks and the CI workflow contain `--extract=pypdfium2`, and a
KB configured for `claude-vision` produces hooks that still do.
**Exit criteria (repo-verifiable):** all of the above; §5 amended to say the machinery ships in v0.2
with all three windows enforced, and §8's v0.4 row updated in the same commit.

### I7a — The paid-path allowlist gate and the invariant amendments (lands first)

**No paid code exists yet, and that is the point.** v0.1's paid-API grep gate never shipped because
it was promised in a section with no owner (rule 8); a gate that arrives in the same increment as
the thing it guards has never once refused that thing. So the gate lands before `extract/claude.py`
exists, and its first job is to prove it fails on a planted violation.

Today `.github/workflows/ci.yml` fails if `anthropic` is imported anywhere under `src/`. The new
gate: one file, `.paid-path-allowlist` at the repo root, lists the permitted paths — exactly
`src/pinakes/extract/claude.py` at v0.2 — and **`check.sh`, CI and the test all read that one
file**, so three copies cannot drift.

- **Gate 1:** every listed path must exist, so a stale entry cannot rot unnoticed. At I7a the listed
  path does not exist yet, so I7a ships the allowlist **empty** and I7b adds the single line in the
  same commit that creates the module — which is itself the gate working.
- **Gate 2:** the paid-client grep (`anthropic|openai|cohere|mistralai|google\.generativeai`) runs
  over `src/` **excluding** the listed paths; any hit is a hard failure with the existing message.
- **Gate 3:** `anthropic` must not appear in `[project.dependencies]` (I1's gate, reused).
- **Gate 4, the one that actually matters,** is a test rather than a grep: after a full free-path
  run — `pnk sync`, `pnk search`, `pnk doctor`, `pnk budget`, and an MCP handshake — `"anthropic"
  not in sys.modules`. Three things make it real rather than decorative:
  1. **It runs in a fresh subprocess** (`uv run python -c …`) which prints its sorted `sys.modules`
     for the test to assert against. In-process it would be defeated by any earlier test's import —
     the same shape as v0.1's `-wal` test, which was correct and then defeated by an environmental
     fact (a read-only connection recreating the files it asserted were gone).
  2. **It skips with a printed reason when `anthropic` is not installed**, because with the package
     absent the assertion is true by construction and can no longer distinguish a clean free path
     from a compromised one. That is the `false_abstain: 0.0` failure (rule 3) reappearing in the
     flagship safety check, so the skip is loud and CI runs a leg where it is meaningful.
  3. **A negative test proves it in the other direction**: the same subprocess is run with an
     injected `import anthropic` preamble, and the test asserts the checker **fails**. A gate only
     ever observed passing is a gate nobody has tested.

`pnk doctor` must report a paid backend's availability **without importing a paid client** —
`importlib.util.find_spec("anthropic")` answers "installed?" and, for a top-level module, adds
nothing to `sys.modules`. Doctor is in gate 4's run list precisely so that this stays true.

**CI grows a third matrix leg.** The `check` job becomes a matrix over `[light]`, `[light,pdf]` and
`[light,pdf,claude]`; the last is where gate 4 and the recorded-fixture paid suite are meaningful.
No job holds an API key, so the leg installs the client and never uses it against the network.

**CLAUDE.md is amended in this increment.** "No code path may make a paid API call outside
`pnk ask --deep`" becomes an enumerated allowlist:

> **Paid entry points are an enumerated allowlist.** Exactly these may spend: `pnk sync` with
> `[extraction] backend = "claude-vision"` or `--extract=claude-vision`; `pnk ask --deep` (v0.4).
> Each goes through the §5 accountant. Adding an entry point edits this list,
> `.paid-path-allowlist` and DESIGN §1 in the same commit.

**Tests:** `tests/test_paid_path.py` — `test_the_allowlist_matches_the_source_tree` (gate 1),
`test_no_paid_client_outside_the_allowlist` (gate 2),
`test_the_free_path_never_imports_the_paid_client` (gate 4, skipping loudly without the extra), and
`test_the_free_path_gate_fails_when_an_import_is_planted` (gate 4's negative).
**Exit criteria (repo-verifiable):** the four gates in `check.sh` **and** CI; the negative test
passes by making the gate fail; the `[light,pdf,claude]` leg green; CLAUDE.md, DESIGN §1, §8 and §9

### I7b — The paid Claude-vision extractor: request shape, validation, retries

`src/pinakes/extract/claude.py` — **the only module in `src/` permitted to import `anthropic`**, and
the line I7a's allowlist gains in this commit. Registered as backend `claude-vision`, reached only
when the manifest says so or `pnk sync --extract=claude-vision` is passed. Every free step precedes
every paid one:

1. **Local pre-checks, zero cost** (PDFScout): page count, encryption detection, request size
   against the documented limits (32 MB per request; 600 pages, 100 for 200k-context models), and
   the free extractor's own text yield against **I3b's fitted floor** — if the free path already
   clears it, the paid path **refuses to spend** unless `--force`, and says so. Paying to re-extract
   a healthy PDF is the most likely way a user loses money by accident.
2. **Estimate and reserve** through I6a, **before every single call**: the first attempt, every
   schema retry, the refusal retry, the truncation retry, and I7c's audit re-extraction each take
   their own pre-call reservation and their own reservation/reconciliation ledger pair. §5 requires
   reserving before *each* call, and a reservation taken once before a page loop that can make up to
   four calls per page is not a cap. The client is constructed as **`Anthropic(max_retries=0)`**:
   the SDK's default of 2 silently turns one `messages.create` into up to three billed HTTP requests
   — and a request retried after a timeout can be billed twice for generation the server already
   completed — so the accountant, not the SDK, owns retry.
3. **Request shape.** A `document` content block placed **before** the text block — `{"type":
   "document", "source": {"type": "base64", "media_type": "application/pdf", "data": …}}`,
   newline-free base64, no beta header — carrying `cache_control: {"type": "ephemeral"}` so pages
   2..N read the prefix at ~0.1× input cost. Two facts about that marker the reservation depends on:
   it is the **5-minute** TTL, and the minimum cacheable prefix is 512 tokens on `claude-opus-5`, so
   a very small PDF will not cache at all and a run resumed after any real gap re-pays the 1.25×
   write. Both are cost facts the report states, not failures. Structured output via `output_config:
   {"format": {"type": "json_schema", "schema": …}, "effort": "low"}` — the current parameter, not
   the deprecated top-level `output_format`, and the reason citations are unavailable (they 400
   together). Thinking is **explicitly** `{"type": "disabled"}`: per-page transcription is not a
   reasoning task, thinking bills at the output rate, and `max_tokens` caps thinking and response
   together so an un-budgeted thinking phase would truncate the JSON body and burn paid retries.
   `claude-opus-5` accepts disabled thinking **only at effort `high` or below**, so the pair is
   pinned together as module constants and the two documented disabled-thinking failure modes are
   checked rather than assumed: tool-call-as-text cannot occur (no tools are declared), and
   `<thinking>` leakage cannot reach the body (`output_config.format` constrains the response to
   schema-valid JSON). The escape hatch, if the human-gated run shows otherwise, is adaptive
   thinking at `low` effort with `max_tokens` raised to budget for it — and the reservation follows
   automatically, because its output bound is `max_tokens`. `max_tokens` starts at 8000.
   `temperature`, `top_p` and `top_k` are never sent: they 400 on this model. An exact-input-token
   refinement may call `client.messages.count_tokens` *inside this module* to tighten the
   reservation immediately before the call; it generates nothing, so its reconciled output is zero
   and its input is treated as billable at the input rate — an over-reservation if the vendor
   charges nothing, never an under-reservation. It is never required, because the estimate must
   exist on an install with no client.
4. **Per-page validation with ≤3 retries** (PDFScout), branching in this order: `stop_reason ==
   "refusal"` is checked **before reading `content`**, counts as a page failure, is retried once and
   then recorded — and it is the *cheap* failure, because a pre-output refusal is not billed at all.
   `stop_reason == "max_tokens"` is checked **next, before schema validation**: a truncated response
   is invalid JSON, and without this branch it would be retried identically three times, all paid,
   all truncating at the same place. A truncated page is re-asked **once** at `max_tokens = 16000`
   under a fresh reservation (the output bound doubled, so the old one no longer bounds it); a
   second truncation records a page failure naming the page. The plan does **not** split a page: the
   sub-page boundary has no ground truth in the corpus, so a split would produce text nothing can
   score.
5. **The fingerprint.** `claude-vision` returns `sha256(backend name, model id, prompt version,
   schema version, request-shape version, LAYOUT_VERSION)`, truncated. It deliberately omits
   `pypdfium2`'s version and pdfium's build, which this backend never loads, and deliberately omits
   `max_tokens`, which is a budget knob rather than a semantic one — a page re-asked at a higher cap
   yields *more complete* text of the same kind, and putting it in the hash would change the
   fingerprint mid-run at exactly step 4's retry. Changing `[extraction] model` therefore produces a
   cache **miss** and, on an already-built index, a §4.4 coherence **refusal** — the two failures a
   shared fingerprint formula would have hidden.

**Tests:** `tests/test_extract_claude.py`, driven entirely by **committed recorded responses** (of
the synthetic corpus only — no real content ever enters this repo), and **unmarked** so the whole
suite runs with `anthropic` absent: a happy multi-page extraction; a schema-invalid page retried and
recovered; a page that exhausts retries; a `stop_reason == "refusal"` handled before `content` is

### I7c — The completeness audit, staging, and all-or-nothing commit

1. **Completeness audit** via I3b's `word_coverage` against pypdfium2's native layer. Pages below
   **I3b's fitted floor** are re-extracted once, and that re-extraction is itself reserved and
   ledgered like any other call. Pages with no usable native layer (the scanned stratum) are
   **exempt and reported as exempt**, with their denominator: `audited N of M, exempt K of M`.
   **With no fitted floor in `baseline.json`, no re-extraction is triggered at all** — coverage is
   still reported, but a threshold with no provenance does not get to spend money (I3b).
2. **Staging and commit.** Each validated page is written to
   `cache/extract/partial/<hash>-<fingerprint>/<page>.json` (temp + `os.replace`) as it completes,
   so an interrupted 200-page run does not re-pay for pages already extracted. The saving is the
   **output** tokens of those pages, which is the expensive half; the resumed run still re-primes
   the prompt cache and re-pays the 1.25× write, because the `ephemeral` marker is a 5-minute TTL
   and a resume hours later finds nothing warm. Stating that here is the difference between a resume
   story that is true and one that reads as "zero re-payment". Only when every page passes is the
   single complete cache entry written and the staging directory removed. A partially extracted
   document writes **no** complete entry and goes to `failures`; `on_exceed = "partial"` is honoured
   at the corpus level (completed documents keep their entries, the run stops cleanly), never at the
   page level — a half-extracted document in the index is the silent truncation §4.6 exists to
   prevent.
3. **`--clear-cache` learns what it is destroying.** Its printed summary (I4) gains the euros the
   cached entries cost, read from the ledger by operation id. CLAUDE.md's "**`.pinakes/` is
   disposable except `ledger.jsonl`**" invariant is amended in this commit to except the paid
   extraction cache too: those entries are derived state that costs real money to derive, which is a
   different thing from disposable.
4. **Flag scope, stated once and in `--help`.** `--extract=BACKEND` overrides `[extraction] backend`
   for one run. `--force` bypasses **exactly one thing**: step 1's refusal to pay for a PDF whose
   free text yield is already healthy. It never bypasses `per_operation_eur`, `daily_eur`,
   `monthly_eur`, the stale-price refusal, or the no-TTY abort — a flag that can widen a hard cap is
   not a hard cap. `--yes` answers confirmation prompts (`confirm_above_eur`, `--clear-cache`) and
   raises no cap.

## Durability sweep (rule 12)

*Which writes lose unrecoverable information if interrupted?*

- **`ledger.jsonl` — the only genuinely unrecoverable write, and it is new.** A crash between the
  API returning and the ledger append loses spend history permanently: money left the account and
  nothing records it. Answered by I6b's two-line reservation/reconciliation protocol — a torn write
  degrades to a *visible* `unknown outcome`, never to a silent zero.
- **Paid staging entries — recoverable, but only at cost.** Regenerable in principle, and that
  regeneration is exactly what the user is paying for; written per page, atomically, consumed on
  resume (I7c). Without them an interrupted 200-page run re-pays for everything. With them it still
  re-pays the prompt-cache write, because that cache is the vendor's and expires in five minutes.
- **Free cache entries — recoverable and free.** Still atomic: a half-written JSON that happens to
  parse is worse than a miss. **The eviction sweep** is the only new delete — derived state only,
  only after a fully successful sync, guarded and tested (I4).
- **Sidecars for PDFs — unchanged and already atomic** (v0.1 I5, rename-based). Re-asserted rather
  than assumed: the ULID a sidecar carries is still the one thing no later command can recompute.
- **The `-wal`/`-shm` lesson (v0.1 I8b) transfers:** cache and staging are *sets* of files under
  directories, so `--clear-cache` and the sweep are tested by listing the directory afterwards,
  never by trusting that one `unlink` was enough.

## Risks specific to this sequencing

Aimed at **machinery**, deliberately: v0.1's risk table enumerated algorithmic risk, and all seven
of its HIGH findings came from areas it never contemplated — durability, file naming, boundary
arithmetic, vacuous metrics, and the gate itself.

| Risk | Why it is machinery | Mitigation |
|---|---|---|
| **Unbounded spend across invocations.** One `pnk sync` is capped; nothing caps the tenth one. Hook-driven freshness makes `pnk sync` machine-driven, so a per-invocation cap is an allowance renewed on every commit | the cap is arithmetic across a *running* total, and per-invocation framing hides that the invocations are the loop | `reserve.py` checks `per_operation_eur`, `daily_eur` **and** `monthly_eur` before every call, computed from the ledger in `[budget] timezone` (I6a boundary tests, I6b's wiring test); the three hooks and `pnk init --ci` force the free backend and say so; no-TTY aborts without `--yes`; the free path is checked first and refuses to pay for a healthy PDF |
| **Retries spend outside the reservation** | one reservation before a loop that makes up to four calls per page is not a cap, and the SDK's own `max_retries=2` turns one call into three billed requests invisibly | every call — first attempt, schema retry, refusal retry, truncation retry, audit re-extraction — takes its own pre-call reservation and ledger pair, spy-asserted; the client is pinned to `Anthropic(max_retries=0)` so the accountant owns retry |
| **The reservation is sized on the wrong unit** | per-page input looks right and is off by an order of magnitude at 200 pages, because caching means each request re-sends the whole document | the estimate is defined over *requests*; the reservation uses the uncached 1.25× rate and lets reconciliation return the saving; a recorded cold-cache run is in the fixture set that proves the bound |
| **The cache key is right and the cache *path* is wrong** | the I8b shape: correlated filenames, correctness argued about one of them | the cache lives under each KB's own `.pinakes/`; a test syncs two KBs holding the same PDF and asserts two files; staging is keyed by the same pair plus page |
| **The fingerprint hashes the wrong things** | one shared formula across two backends hashes a library the paid path never loads and omits the model that produced the text — a cache hit serving old-model text, and a coherence gate equally blind | fingerprinting is a per-backend protocol method; `claude-vision` hashes model id, prompt, schema, request shape and `LAYOUT_VERSION`; a test asserts that changing `[extraction] model` both misses the cache and refuses the query |
| **Partial or interrupted extraction leaves a document half in the index** | a truncated document is exactly the silent quality loss §4.6 exists to prevent, and nothing in the output reveals it | all-or-nothing commit: no complete cache entry until every page passes, and the document goes to `failures`; `on_exceed = "partial"` is corpus-level only, stated in `--help` and §5 |
| **The paid-path allowlist erodes, or its decisive gate is inert** | a one-line import in a new module quietly makes the free path paid; and a behavioural gate that asserts a package is absent is vacuously true wherever that package is not installed | one `.paid-path-allowlist` read by `check.sh`, CI and the test; the gate lands before the code it guards; it runs in a fresh subprocess, skips loudly where it cannot be meaningful, is exercised on a `[light,pdf,claude]` CI leg, and has a negative test that plants an import and asserts it fails |
| **Scanned-PDF quality cannot be measured by the audit that measures everything else** | the completeness audit's witness is the native text layer, and a scanned page has none — the gate is blind on precisely the stratum the feature exists for | the audit reports `exempt K of M` rather than scoring exempt pages as passing; the scanned stratum's ground truth is hand-authored from the generator's spec; its numbers land in §9 with date, model and cost, labelled as measured on synthetic rasters |
| **Price-table staleness, and the USD→EUR rate inside it** | the manifest prices in EUR and the vendor in USD; the rate is a second number that goes stale with nothing saying so, and a ledger that records only a EUR figure cannot be re-derived later | `usd_per_eur` carries the same `as_of` as the prices; every ledger line records `cost_usd`, the rate and the `as_of`, and EUR is computed at read time; `pnk budget` shows which rate each window used; `pnk doctor` WARNs past `max_price_age_days`; an estimate against stale data refuses rather than guessing. Not a CI gate — see I6a |
| **A threshold that spends money is chosen by intuition** | `word_coverage`'s floor triggers paid re-extraction, so a guessed value is a guessed invoice | fitted in I3b on the I2 corpus with the scanned stratum as the exempt control, committed with `fitted_on`; absent a fitted floor the audit reports and refuses to spend, the same fail-closed shape as `confidence: unknown` |
| **The recorded-fixture harness diverges from the real API** | a fake that encodes only the happy path proves nothing about retries, refusals or truncation | fixtures include a refusal, a schema-invalid page, a truncated page and a page that drops content; the one human-gated real-API run at I7b is the reconciliation, and its date and model are recorded |
| pypdfium2 or anthropic warns at import, and `filterwarnings = ["error"]` turns a whole matrix leg red | a pyproject setting colliding with a dependency, invisible until the extra is installed | I1 probes **both** before anything depends on them; the fix, if needed, names that exact warning — never a blanket ignore |
| the committed PDFs drift from their generator | a byte diff nobody runs | `make corpus` is a gate in `check.sh`, not an instruction — byte-exact for the sixteen text-layer fixtures, within a stated pixel tolerance for the three rasters, because a raster gate that demands bit-exactness fails on the next renderer bump instead of on a real change |
| quality thresholds are chosen from the same corpus they score | v0.1 shipped precisely this for confidence and had to label the result a floor | the corpus is *ground-truth-labelled*, so the metrics are measurements; only the thresholds come from it, and the report header says so |
| a `schema_version` bump strands users who will never index a PDF | a forced rebuild is a machinery cost with no feature benefit to them | announced in the CHANGELOG and in the error's remedy; rebuilds are free and `ledger.jsonl` survives |
| pdfium builds, or the layout algorithm, change extraction silently | every stored span would be stale with nothing saying so | the free backend's fingerprint includes the pypdfium2 and pdfium versions **and** `LAYOUT_VERSION`, so either change is a cache miss **and** a per-document coherence refusal |
| a PDF-shaped file that is not a PDF, or a 400 MB PDF, hangs sync | resource behaviour, not parsing behaviour | I3b's reader is the only free I/O boundary; a corrupt-header fixture, an encrypted fixture and a size guard with a stated limit are tested there by name; the paid path re-checks the 32 MB / 600-page API limits before encoding |
