## Goal

A PDF dropped into `docs/` is indexed, chunked, retrievable and citable by page — and the quality of
the text that made it in is **measured, not assumed**. DESIGN §9 calls PDF extraction *"the most
likely source of silent quality loss"*; the release exists to make that loss visible before it
reaches a user's answers.

v0.2 ships **two** extractors: a free, local, offline default (`pypdfium2`) and an **opt-in paid
Claude-vision extractor** that puts scanned PDFs in scope for the first time. Because a paid path
exists, v0.2 also ships **the whole budget machinery**: §5 says the budget system ships in the same
release as the first thing that can spend, "which is the honest ordering", and that first thing is
now the extractor rather than `pnk ask --deep`. Not scope creep — the design's own rule applied to
the user's decision. Every increment ends **green** (`./check.sh`, equivalently `make check`) and
**committed on its own**, so any regression bisects to one increment.

**Checked dead end — do not re-litigate.** Claude's **citations API** was investigated as a source
of exact character offsets and ruled out. Verified in the Anthropic API reference: a PDF `document`
block returns **`page_location`** (`start_page_number` / `end_page_number`, 1-indexed) —
**`char_location` is returned only for plain-text documents**. Citations are also a paid, query-time
call and are **incompatible with `output_config.format`** (400), the mechanism I7b uses to validate
extraction. So they cannot supply the offsets, cannot be free, and cannot coexist with the
extractor. Decision 4 stands.

**Checked and declined — server-side refusal fallbacks.** The Anthropic guidance is to ship
`claude-opus-5` code with the `fallbacks` parameter on by default (`fallbacks: "default"` under the
`server-side-fallback-2026-07-01` beta), because Opus 5's safety classifiers can decline a request
and a fallback silently rescues it. **v0.2 declines it, deliberately**: a rescued request is served
by a *different model*, and the extraction fingerprint (I7b) hashes the model id. A fallback would
therefore write text produced by one model into a cache entry claiming another — precisely the
silent-provenance failure the fingerprint exists to prevent, and undetectable afterwards. A refusal
here is a page failure with a recorded reason, on a synthetic corpus, which is a survivable outcome;
mislabelled cached text is not. Revisit only if the fingerprint learns to record the model that
actually answered, per page.

## Ground rules (apply to every increment)

- **The gate is an artifact, not a list of commands** (rule 1): `./check.sh` / `make check` passes
  immediately before `git commit`, and every new gate is **added to that script**, never described
  in prose. Two v0.1 commits landed red because the gate was a shell pipeline. New gates and owners:
  extras-not-core (I1), corpus-regenerates (I2), `pdf-eval` baseline (I3b), price-table
  well-formedness (I6a), paid-path allowlist (I7a).
- **A gate that cannot run must say so and still be a gate.** `pdf-eval` and the corpus's scanned
  stratum need `pinakes[pdf]`; gate 4 of the allowlist needs `pinakes[claude]`. Each **skips with a
  printed reason** when its half of the environment is absent (`pdf-eval: skipped — pinakes[pdf]
  not installed`), never silently, and a test asserts the printed reason — a skip nobody can see is
  the vacuous-metric failure (rule 3) wearing a different hat. CI runs the legs that make each gate
  meaningful.
- **Worktree + branch per increment**, `YYYYMMDD_HHMM-i<N>-<slug>` per CLAUDE.md.
- **No inline type suppressions at all** (rule 7). Both that existed in v0.1 hid real defects; the
  Anthropic SDK's response unions are the temptation here, so narrow with an explicit
  `block.type == "text"` check, never a cast.
- **Test-machinery rules, beside the algorithm rules** (rule 5): a fake must not derive its answer
  from the input under test, so **the fixture generator is not the extractor** and each fixture's
  ground truth is authored from its *spec*; a stand-in must be adversarial in the dimension it
  stands in for, so the registered `fake` extractor returns deliberately ugly text (double spaces, a
  stray running head, a hyphen join) and the **recorded** paid-API fixtures include a refusal, a
  schema-invalid page, a truncated (`stop_reason == "max_tokens"`) page and a page that drops
  content; no `or` in an equality assertion; a skip condition must check **every half** of its
  environment claim.
- **Two markers, stated scope.** `pdf` marks tests needing `pinakes[pdf]`, and its predicate checks
  the extra imports **and** the fixture exists. `paid` marks **only** tests that make a real API
  call, and its predicate checks `anthropic` imports **and** a key is present **and**
  `PINAKES_ALLOW_SPEND=1` is set. The recorded-fixture suite is **unmarked**: it must run with
  `anthropic` absent, which is what proves the registry seam. `PINAKES_ALLOW_SPEND` is a **pytest
  condition only, never a product guard** — the product's opt-in is already explicit
  (`[extraction] backend`, `--extract=`, the accountant), and a second env-var gate would be a
  footgun a user sets once in a shell profile and forgets.
- **Test-environment configuration lands in I1** (rule 6): both markers and their multi-part
  predicates, `SOURCE_DATE_EPOCH` pinning for fixture generation, and a probe that **both**
  `pypdfium2` and `anthropic` import silently under `filterwarnings = ["error"]` — a warning at
  import turns every test in that leg red, and the `anthropic` leg is new in this release.
- **Retrospectives are an input, not only an output** (rule 10): re-read `docs/RETROSPECTIVES.md` at
  the *start* of each increment, and land findings and fixes as their **own commit** — v0.1 lost
  that in 5 of 15 increments, and bisectability depends on it.
- Docs rule (CLAUDE.md): a user-facing surface added in an increment updates `docs/DESIGN.md`, the
  README and `--help` **in the same commit**; every date carries `HH:MM`; the CHANGELOG
  `[Unreleased]` line lands with the code, and `[0.2.0]` is cut by I9.
- **CI never spends money.** No CI job holds an API key; the paid path is exercised end to end from
  committed recorded responses. Real-API runs are human-gated (rule 9), with date, model and cost
  recorded.
- **v0.2 must not move the demo KB's eval numbers.** If `make eval` shifts, that is a defect to
  explain, not a tuning opportunity (CLAUDE.md's retrieval rule).

## Prior art: PDFScout

[PDFScout](https://github.com/lucagattoni/PDFScout) (the user's own project, MIT) is a LangGraph
multi-agent PDF extractor on Claude's native PDF vision. I7b is written against it deliberately, and
says so in its module docstring.

**Borrowed.** (a) **The completeness audit against the PDF's own embedded text layer** — PDFScout's
`coverage_node` compares significant words (alphabetic, ≥5 chars, NFKC-folded, order-free) from the
native layer against the model's per-page output and re-extracts pages that dropped or duplicated
content. Here it is *free*, because pypdfium2 already produced that layer in I3b, so it is the paid
path's quality gate at zero marginal cost. It brings PDFScout's own caveat too, which becomes a risk
row: a scanned page has **no usable native layer**, so the audit is blind on exactly the pages the
paid path exists for, and the corpus's hand-authored ground truth is what covers those. (b)
**Per-page schema validation with bounded retries** (≤3), so a malformed page is re-asked rather
than silently truncating the document. (c) **Local pre-checks before any API cost** — page count and
encryption detection, offline.

**Rejected after pass 2 — provider-side prompt caching as the cost strategy.** PDFScout re-sends the
whole document on every per-page request and reports pages 2–N at ~10% of input cost. That figure is
real but it is a *hit-path* figure over a cost the design creates: re-sending an N-page document N
times is `N × doc_tokens` of input where sending each page once is `N × page_tokens`. The quadratic
term is what caching then discounts. Two consequences make it unusable rather than merely
expensive: `doc_tokens` exceeds `claude-opus-5`'s **1M context window** at roughly **166 pages** at
this plan's own 6,000-tokens-per-page constant — below the 600-page API limit the pre-check tests,
and below the 200-page case this plan works through — and the `ephemeral` marker is a **5-minute**
TTL, so any run longer than five minutes re-pays the 1.25× write repeatedly. v0.2 sends a **K-page
slice** instead (decision 8): each page is sent exactly once, input is linear, there is no page
ceiling, and no cost claim depends on a cache that expires mid-run. Caching may return in v0.3 as an
optimisation *on top of* a linear baseline, where a cache miss costs a discount rather than an
order of magnitude.

**Rejected.** *LangGraph and the multi-agent graph* — pinakes has one extraction task, and a graph
framework is exactly the "second, worse agent framework" §9 names as a risk. *The classifier and
hierarchy agents* — they produce a document tree; pinakes needs linear text with page spans, and a
hierarchy would be a second structure with no consumer (v0.1's I6 is the record of what an unused
structured column costs). *SQLite checkpoint/resume* — resume uses per-page staging files inside the
extraction cache instead (I7c), rather than a second durability surface beside the cache and
per-document transactions that already exist. *Per-page parallel fan-out, in v0.2* — the hard cap is
a **running** reservation total (§5) and concurrent calls can breach it between reservation and
reconciliation; parallelism lands in v0.3 once the accountant has a ledger to prove itself against.

## What this plan deliberately does NOT decide

- **Table structure recovery.** The table stratum measures whether a table's text survives in
  readable order with label/value adjacency intact — not whether a grid is reconstructed as a grid.
- **PDF outlines/bookmarks as a `heading_path` substitute.** Pages are the unit v0.2 ships.
- **The Files API** (`files-api-2025-04-14`) instead of base64 document blocks. It uploads once and
  references a `file_id` across requests, but needs the beta header on **both** the upload and the
  message call plus an upload lifecycle to clean up. Under decision 8 each request carries a
  *different* K-page slice, so there is nothing an upload would be reused across within a document.
  **Default: base64 slices.** Revisit only if slices become large enough that upload bandwidth, not
  tokens, is the cost.
- **Figures, embedded images, captioning** beyond what the paid extractor's page output already
  says; Office, HTML, email, chat (§1 rules them out); any change to chunking parameters, fusion,
  reranking or the confidence signal; `pnk link` and cross-KB traversal (v0.3); `sqlite-vec` (v0.5).
- **`pnk ask --deep`** — still v0.4; v0.2 ships the budget machinery it will use, not the loop.
  **Default:** the accountant's "operation" for v0.2 is one `pnk sync` invocation — which bounds a
  single invocation and nothing else, so the day and month windows (I6a) are what bound a *sequence*
  of them.

### I1 — Extras, the extractor seam, and an honest core-only failure

`pyproject.toml` gains `pdf = ["pypdfium2>=5.12"]` and `claude = ["anthropic>=0.116",
"pinakes[pdf]"]` under `[project.optional-dependencies]`. Both floors verified against PyPI
**20260727 16:00**: pypdfium2 5.12.1 is the latest release (uploaded 20260717) and 5.x is a major
jump from the 4.x series that touches the character-level text API I3b targets, so the floor is
deliberately at 5.12 rather than `>=5`; `anthropic` 0.116.0 exists (uploaded 20260702) and 0.120.0
is the latest (20260724), so the floor admits the current SDK without pinning to it. **`[claude]`
depends on `[pdf]`, not beside it**: the paid path slices PDFs into K-page sub-documents, pre-checks
the free text yield before spending, and audits its output against the native text layer — three
pypdfium2 uses, so `pip install "pinakes[claude]"` without `[pdf]` would install a backend that
cannot run its own pre-checks.

`src/pinakes/extract/` becomes a package. `__init__.py` holds:

- **The `Extractor` protocol**, `extract(path, ctx) -> ExtractedText` and `fingerprint_inputs() ->
  dict[str, str]`. The `path`-only signature the draft carried could not carry what I7b needs — the
  accountant, the ledger writer, the staging directory, `--force`, and page-range resume — so the
  context is explicit from the start rather than retrofitted at the increment that discovers it.
  `ExtractionContext` is frozen and defined here; its paid fields are `None` on the free path. -
  **`ExtractedText(text, page_spans, per_page_provenance)` as the one type crossing the seam.** Each
  backend runs its own assembly and returns finished text: the free backend calls I3a's `assemble()`
  over `RawPages`, the paid backend builds it from per-page JSON. `RawPages` / `Page` / `Block` /
  `CharSpan` remain, but they are the **free backend's internal geometry**, not the seam — the paid
  backend has no coordinates to put in them (decision 10), and a protocol that demanded geometry
  would have forced it to invent some. I4 caches `ExtractedText`, I5 chunks it: one type, three
  consumers, no cache-hit path where the consumer wants a field the cache never stored. - **The
  registry** — open, module-level, keyed on backend name, with lazy imports: the single best
  structural call of v0.1 (I7), and what lets the real CLI be driven end to end with neither extra
  installed. Both names (`pypdfium2`, `claude-vision`) are **registered at I1** with loaders that
  raise `ExtractionError("the pypdfium2 adapter lands in I3b")` / `ExtractionError("the
  claude-vision extractor lands in I7b")`; manifest validation checks membership in the key set and
  **never imports**, so an unknown backend is rejected at I1 without either extra being installable.
  - **Fingerprint inputs, resolvable without importing the backend.** Each backend's *inputs* are
  declared in the registry entry (a client-free dict of version strings and constants); the hash is
  computed by a shared pure function over that dict. §4.4's per-document coherence check (I5) runs
  on **every query**, so if it had to import a backend to ask for its fingerprint, the free query
  path would import `anthropic` on any KB holding one paid document — defeating I7a's gate 4, which
  passes today only because its run list contains no paid documents. Inputs that genuinely need the
  installed library (pypdfium2's version, pdfium's build) are read through `importlib.metadata`, not
  by importing it.

`errors.py` gains `ExtractorMissingError` (names the extra) and `ExtractionError`, both routed
through the existing `_rebuild` helper so they survive pickling (v0.1 I1/I4). `chunk.source_type`
maps `.pdf` → `"pdf"`. `sync._index_document` **routes on `source_type`** instead of unconditionally
calling `read_text(encoding="utf-8")`; a PDF today raises `UnicodeDecodeError` and is logged as an
opaque `index`-stage failure.

**The manifest gains the whole `[extraction]` block here, and `pnk sync` gains `--extract`.** Both
keys (`backend = "pypdfium2"`, `model = "claude-opus-5"`) and the flag land in the increment that
owns the registry, not in the increments that first *consume* them: I6a's estimator needs a model id
and I6b's hooks are written to contain `--extract=pypdfium2`, so if the flag arrived at I7b as the
draft implied, I6b would ship a `pre-commit` hook carrying an argument `pnk sync` rejects — blocking
every commit for anyone who ran `pnk install-hooks` between I6b and I7b. `--extract=BACKEND`
overrides `[extraction] backend` for one run and is validated against the registry's key set, so at
I1 it already rejects an unknown backend and already accepts `claude-vision` with the honest
"lands in I7b" error.

`pnk doctor` gains a `pdf extractor` check: OK when importable, WARN naming the extra when `include`
can match `*.pdf`. Test-environment configuration per rule 6, listed in the ground rules. **Tests:**
registry dispatch and a monkeypatched import failure raising `ExtractorMissingError` naming
`pinakes[pdf]` — **and a second, symmetric case naming `pinakes[claude]`**, since a one-backend test

those same three legs in this commit** — the draft left the matrix until I7a, so I2 through I6b
would have landed with two of their three environments proved only on a developer's machine while
the ground rules promise "CI runs the legs that make each gate meaningful"; a new `check.sh` gate
fails if `pypdfium2` or `anthropic` appears in `[project.dependencies]`; `pnk doctor` prints the new
check in both install states.

### I2 — The synthetic hard-case PDF corpus and its generator

`tests/pdf-corpus/`: a committed generator, the committed PDFs it produces, and one hand-authored
`<name>.expected.txt` per fixture. **No real-world PDF is ever committed** (CLAUDE.md: the repo is
the engine). Ground truth comes from the generator's *spec*, never from extractor output — otherwise
the test asserts only that the extractor agrees with itself. Sized **per stratum, not in aggregate**
(rule 4 — v0.1 sized its golden set at ≥40 in aggregate and still ended with an 8-question no-answer
stratum it had to label a floor):

| Stratum | n | Must contain |
|---|---|---|
| two-column | 3 | reading order across a gutter; a caption straddling both columns; a left column ending mid-sentence |
| tables | 3 | a bordered grid; a borderless whitespace-aligned table; one with a spanning header cell |
| headers / footers | 3 | a repeating running head; page numbers; a footer present only on page 1 |
| ligatures & hyphenation | 3 | U+FB01/U+FB02; a soft hyphen; a word split across a line break **and** one across a page break |
| **scanned / image-only** | 3 | **2 pages each, 6 in total**: a page rastered from known glyph coordinates with **no text layer**: clean, skewed 2°, low-contrast. Two pages rather than one so the K-page slicing path (I7b) is exercised at a slice boundary by the corpus itself. This is the stratum the paid path exists for |
| pathological | 2 | a text layer in invisible render mode; a truncated/corrupt-header file |
| baseline | 2 | plain single-column prose, one page and twelve pages |

Nineteen documents, ≥45 pages, **≤ 2 MB committed in total, of which the scanned stratum's six
pages are ≤ 1.5 MB** — at 150 dpi grayscale Flate that is ~250 KB per page, which the sub-budget
accommodates with headroom. Stated numbers, asserted by a test, so a fixture cannot balloon
unnoticed.

The generator writes raw content streams for the sixteen text-layer fixtures, no layout engine and
**no dependencies**: those fixtures are not documents, they are **text layers with known
coordinates** using the PDF base-14 fonts, and a layout engine would hide the variable under test
behind its own decisions.

**The scanned stratum is generated differently, and gated differently.** It rasters the *same*
coordinates as its text-layer twin, so its ground truth is identical to the twin's — which makes
free-vs-paid directly comparable on the same content. Producing that raster needs a renderer and an
image writer: `pypdfium2` (the `pdf` extra, already present) renders the twin's page to a bitmap,
and **Pillow** (new, in the dev dependency group only — never core, never an extra) applies the skew
and contrast transforms and writes the image-only PDF at 150 dpi, 8-bit grayscale, Flate-compressed.
JPEG is never used: JPEG encoders differ across builds, and lossless Flate keeps the pixels the
generator produced. Rendering is not extraction, so rule 5's "the generator is not the extractor"
holds — the ground truth still comes from the spec.

**Byte-identical regeneration is not achievable for rasters** and pretending otherwise would make
the gate CI-flaky on any pdfium or Pillow bump. So the gate splits: the sixteen text-layer fixtures
must regenerate **byte-identically**; the three scanned fixtures are checked by structure (no text
layer, expected page count, image geometry and colour mode) plus a **mean absolute per-pixel
difference ≤ 2/255** against the committed image. A mean, not a max: a resampling change at glyph
edges must not fail the build, a moved word must. A renderer bump that exceeds the tolerance is
handled by regenerating and committing the new rasters in a commit that says so.
**Tests:** `tests/test_pdf_corpus.py` — byte-identical regeneration of the text-layer strata (fixed
producer string, `CreationDate`/`ModDate` from `SOURCE_DATE_EPOCH`); the scanned stratum's
structural + tolerance check, `pdf`-marked and skipping with a printed reason when the extra or
Pillow is absent; every fixture has a ground truth and every ground truth a fixture; stratum counts
match the table, so the corpus cannot silently shrink; the committed byte budget holds.
**Exit criteria (repo-verifiable):** `make corpus` leaves no diff on the text-layer strata and no
tolerance breach on the scanned stratum, and that check is a gate in `check.sh` that skips the
scanned half with a printed reason when its dependencies are absent. **Not** an exit criterion: any
claim about extraction quality — nothing extracts yet.

### I3a — Extraction core, pure (rule 11: the pure half)

`extract/layout.py`, operating only on the I1 types — no PDF library, no filesystem:

- `blocks_from_chars(chars) -> list[Block]` — pdfium's text API is **character-level**, and turning
  a character stream into blocks is the single densest piece of logic in the extraction path. It
  lives here, pure and table-driven against hand-built character streams, rather than inside the I/O
  adapter where it would be reachable only through an end-to-end corpus score (rule 11).
- `reading_order(page)` — column detection by x-gap clustering, then top-to-bottom within a column.
- `strip_running_heads(pages)` — a line recurring in the same y-band on ≥ *T* of pages, digits
  normalised, is a running head. ***T* = 0.6, and it is fitted, not guessed** — it changes the
  extracted text and therefore the free backend's fingerprint, so a bare constant would be exactly
  the "threshold with no provenance" I3b refuses elsewhere. I3b fits it over the headers/footers
  stratum (whose spec states which lines are running heads and which are genuine headings) and
  commits it with `fitted_on` beside the two spending floors; 0.6 is the starting value the fit
  begins from, not the shipped answer. **The threshold ships with its denominator**: the result
  reports `suppressed N of M pages`, so a wrong *T* is visible instead of silently eating a real
  heading.
- `join_hyphenation(lines)` — join a trailing hyphen or U+00AD when the continuation starts
  lowercase; never join across a heading or a suppressed running head.
- `normalise(text)` — ligature expansion (U+FB00–U+FB06), NFC, an explicit whitespace policy.
- `assemble(pages) -> ExtractedText(text, page_spans)` — **offsets are emitted with the text, never
  accumulated afterwards** (v0.1 I6: spans from `match.start()` rather than a running total are
  exact by construction rather than by accounting).
- `LAYOUT_VERSION` — a hand-bumped constant hashed into the fingerprint of **every backend that runs
  this module**, because a change to reading order or hyphenation changes the extracted text as
  surely as a library upgrade does, and would otherwise be a silent cache hit. At v0.2 that is the
  free backend only: the paid one returns per-page text with no coordinates and bypasses `layout.py`
  entirely (decision 10), so hashing `LAYOUT_VERSION` into it would make an ordinary free-path
  refactor invalidate every paid cache entry and refuse every query on a paid KB until the user paid
  to re-extract. A free-path constant must not be able to send an invoice.

**Tests:** `tests/test_extract_layout.py`, table-driven — one case per rule, plus the compound cases
a table cannot express: a two-column page continuing mid-sentence into the right column; a running
head that is a genuine heading on exactly one page; a hyphenated word split across a page break
where the next page opens with a running head. `blocks_from_chars` gets its own dense table:
characters out of reading order, a word split across two text runs, overlapping bounding boxes, a
zero-width character, and a page with no characters at all. Two property assertions over **every**
case: `"".join(text[s:e] for s, e in page_spans) == text`, and `page_spans` contiguously covers `[0,
len(text))`. **Exit criteria (repo-verifiable):** one named test per rule and per compound case;
both properties hold across all of them; an import-graph test asserts `layout.py` imports no PDF
library.

### I3b — The pypdfium2 adapter, the quality metrics, and the two fitted floors (rule 11: I/O)

`extract/pdfium.py` is a **thin reader**: open a file, guard its size against **256 MB** (a stated
number, tested at the boundary — large enough that no legitimate corpus document trips it, small
enough that a runaway file fails fast instead of exhausting memory), refuse an encrypted or
corrupt-header file with a named error, and emit `list[CharSpan]` per page for I3a's
`blocks_from_chars` to assemble. It also exposes **`slice_pages(path, first, last) -> bytes`**,
which writes a K-page sub-document — I7b's request unit (decision 8), put here because this is the
module that owns pdfium and I7b must not become a second PDF I/O boundary. **The API is verified
against pypdfium2 5.12.1 (20260727 17:00), not assumed:** `PdfDocument.new()`,
`import_pages(pdf, pages=None, index=None)` and `save(dest)` all exist, and a round trip over a
12-page document produced a 5-page slice and a 2-page short final slice, ~1 KB each. Decision 8
rests on this call existing in the BSD-licensed library the project already chose, so it is checked
here rather than discovered at I7b. Everything that decides *what the text is* lives in the pure
half; what remains here is
I/O, and that is where review effort is budgeted (rule 11's corollary: v0.1's pure half produced one
finding and the I/O half four, all environmental).

Its option set is **pinned and hashed** into the fingerprint. Fingerprint **inputs** are declared in
I1's client-free registry entry and hashed by one shared pure function — per-backend *inputs*, not
one shared formula, because a shared formula would hash `pypdfium2`'s version for a backend that
never loads it while omitting the model that actually produced the text (pass 1, H4); and inputs
rather than a method on the backend, because §4.4's per-document check runs on every query and must
never import a paid client to ask a question about a fingerprint (pass 2, M-1). This backend's
inputs are backend name, pypdfium2 version, pdfium build, the option dict, `LAYOUT_VERSION` and the
fitted running-head threshold *T*; the paid backend's are stated in I7b. The value is written to
`documents.extraction_fingerprint` (with `documents.extraction_backend`) at sync, and into the I4
cache key.

`extract/quality.py` scores an extraction against a ground truth. **Every rate ships with its
denominator as a co-metric** (rule 3 — v0.1's `false_abstain: 0.0` was vacuous and would have passed
a CI gate forever):

| Metric | Numerator | Denominator |
|---|---|---|
| `char_recall` | expected non-space characters found, in order | expected non-space characters |
| `order_fidelity` | LCS length over word sequences | expected word count |
| `junk_rate` | extracted words absent from the ground truth | extracted word count |
| `pair_adjacency` | asserted (label, value) pairs within **80** characters of each other | asserted pairs |
| `word_coverage` | significant native-layer words present in the extraction | significant native-layer words |
| coverage | `documents_scored`, `pages_scored` | `documents_total`, `pages_total` |

`word_coverage` is the PDFScout completeness audit, defined here as a pure function of two strings
so it can be tested against hand-computed answers; I7c consumes it as the paid path's re-extraction
trigger, and a metric that can be wrong on a known input is not fit to gate anything.

**Both thresholds that later cost money are fitted here, on the I2 corpus, recorded with their
provenance — and *shipped in the wheel*.** Neither is chosen by intuition, and neither is defined in
the increment that spends against it:

- **The `word_coverage` re-extraction floor** (consumed by I7c). Fitted as the 5th percentile of
  `word_coverage` over the six non-scanned strata, **comparing pypdfium2's extraction against the
  document's own native text layer** — the *same pair* the floor is applied to at I7c, where the
  comparison is (native layer → Claude's output). The draft fitted it against the hand-authored
  ground truth instead, a different distribution: on a hard two-column fixture pdfium may recover
  0.85 of the ground truth and drag the floor down there, while Claude-versus-native-layer on the
  same page sits near 0.98 — so the floor would never fire and the audit that exists to catch
  dropped content would be inert. `baseline.json` records **which pair produced the number**, so
  this cannot be re-confused. The scanned stratum is the **exempt control** — no native layer,
  `word_coverage` undefined, never scored as a pass. - **The `text yield` floor** (consumed by I7b's
  free-path pre-check *and* I8's `pnk doctor` check). Non-whitespace characters per page: the three
  scanned fixtures are the positive control at zero, the twelve-page baseline the negative control.
  Defined here rather than in I8 because two increments consume it and neither may define it for the
  other.

**Both floors ship as package data, and both fail closed when absent.** `extract/floors.toml` sits
beside I6a's `prices.toml` in the wheel, written by the fitting run and carrying each value's
`fitted_on` (corpus revision + `YYYYMMDD HH:MM`). `tests/pdf-corpus/baseline.json` is a *test*
artifact and is not installed, so a draft that kept the floors only there gave every installed copy
of pinakes no floors at all — while three runtime consumers on a user's own KB depend on them
(I7b's don't-pay-for-a-healthy-PDF guard, I7c's re-extraction trigger, I8's doctor check).
**Absent a fitted floor, neither consumer spends**: the audit reports coverage and triggers no
re-extraction, and the paid path refuses to run rather than paying to re-extract a PDF it cannot
prove is unhealthy. The draft stated this rule for `word_coverage` only, which would have left
I7b's guard silently disabled — every installed user paying to re-extract healthy PDFs. Same
fail-closed shape as v0.1's `confidence: unknown`, and the reason is identical: a threshold with no
provenance is a number, not a measurement, and both of these spend money. The running-head threshold
*T* (I3a) is fitted in the same run and written to the same file; it costs no money, so its absence
is a startup error rather than a refusal to spend.

**The free-vs-paid pipeline difference is measured here, not assumed.** Decision 10 has the paid
backend bypass `layout.py`, so running-head stripping and reading order differ between a free and a
paid extraction of the same page. `make pdf-eval` therefore scores the scanned stratum's *text-layer
twins* through both pipelines once I7b exists and records the delta per metric in `baseline.json`;
a difference is expected and acceptable, an *unexplained* one is a finding. Until I7b lands the
paid column is absent rather than assumed equal.

`python -m pinakes.extract.quality tests/pdf-corpus` writes a JSON report; `--baseline` compares
**per stratum** with a tolerance, mirroring `eval.compare`; `make pdf-eval` wraps it and joins
`check.sh` **and CI, as its own job, in this commit** — the draft left the CI job until I9, so the
extraction-quality baseline would have gated nothing across six intervening increments. It skips
with a printed reason when `pinakes[pdf]` or the corpus is absent (I1's exit criterion is that the
gate is green under `--extra light`). The scanned stratum's expected free-path `char_recall` is
**0.0** — a declared zero with its fixtures named, not a passing score. **Tests:**
`tests/test_extract_quality.py` — each metric on hand-built strings with hand-computed answers;
`documents_scored == documents_total` for every stratum; a planted regression (one fixture's
extraction truncated to its first page) **fails** the baseline comparison; both fitted floors are
present in the **shipped** `floors.toml` with a `fitted_on` timestamp
(`::test_floors_are_installed_package_data` reads them through `importlib.resources`, the way a user
would, not through a repo-relative path); the audit refuses to trigger a re-extraction when the
`word_coverage` floor is absent, **and the paid path refuses to spend when the text-yield floor is**
— one test per floor, because a rule stated for one and tested for one is a rule the other never
had. `tests/test_extract_pdfium.py` (`pdf`-marked) — the reader's own contract: the corrupt-header
fixture raises a named error rather than crashing, the size guard fires at 256 MB, an encrypted file
is refused before any parse, the invisible-render-mode fixture yields the characters it actually
contains, a zero-page file is an error not an empty success, and `slice_pages` returns a valid
sub-document whose page count and text match the requested range (including a range that runs past
the last page). `tests/test_check_script.py` — `pdf-eval` skips with its printed reason when the
extra is absent, and `check.sh` still exits 0. **Exit criteria (repo-verifiable):** `make pdf-eval`
green against a committed `tests/pdf-corpus/baseline.json` **and green as a CI job**; the
planted-regression test passes by failing the comparison; every stratum's denominators are non-zero;
both floors committed in `floors.toml` with values and `fitted_on`, and installed by the wheel;
DESIGN §7 amended in this commit.

### I4 — The extraction cache

`extract/cache.py`. One JSON per entry — `{schema, content_hash, backend, fingerprint, page_count,
page_spans, text, per_page_provenance, operation_id, call_ids}` — because a text/JSON pair
introduces a half-written-pair corruption class that need not exist. It stores exactly I1's
`ExtractedText` plus its provenance, so what a cache **hit** returns is what a cache **miss**
returns; a draft in which I5 consumed "the extraction's blocks" while the cache stored only text and
spans would have worked on every miss and failed on every hit, which is rule 2's failure shape in
the one increment pair the plan cites to justify the trace test.

`operation_id` and `call_ids` are the join key to the ledger. Without them I7c's promise that
`--clear-cache` prints what the cached entries cost is unimplementable: no cache entry recorded a
call and no ledger line records a document, so there was nothing to join on. `call_ids` is a list
because one paid document is several K-page requests (I7b); both are `null` for a free extraction,
which costs nothing and joins to nothing. The ledger's no-content rule is untouched — the identifier
travels from the cache to the ledger, never document text from the ledger to anywhere.

Written to a sibling temp and `os.replace`d. Invalidation is **by key, never by mutation**: an
edited PDF or a changed fingerprint simply misses.

```text
.pinakes/
├── index.db          ← disposable, rebuilt
├── ledger.jsonl      ← NEVER touched (§6.3)
└── cache/extract/
    ├── <content_hash>-<fingerprint>.json      ← a complete extraction
    └── partial/<content_hash>-<fingerprint>/  ← per-page staging, written only by I7c
```

Eviction: after a **fully successful** sync, entries whose `content_hash` matches no active document
are removed — never after a run that recorded failures, never during `--sidecars-only`, never during
`--rebuild` before the swap succeeds, and **never for an entry written by a paid backend**. That
last exclusion is the same rule I7c writes into CLAUDE.md, applied to the path that would otherwise
break it silently: a soft-deleted document (§6.4 keeps `state = deleted`) is not an "active
document", so a routine delete or an un-sidecarred rename would sweep away an extraction the user
paid for — with no prompt and no printed euros, while the *manual* `--clear-cache` gains both.
Paid orphans are **reported** by the sweep and by `pnk doctor` (`paid orphans: N, X.XX EUR`) and
removed only by an explicit `--clear-cache`. `pnk sync --clear-cache` (named in §6.3, never
implemented) empties `cache/` only; `--rebuild` leaves it alone, which is the whole point of a
cache.

**`--clear-cache` confirms before it destroys.** It prints the entry count and bytes it is about to
remove and requires a `y`; `--yes` skips the prompt for cron use. I7c extends the printed summary
with the euros those entries cost, read from the ledger, and amends CLAUDE.md's
"`.pinakes/` is disposable" invariant to except the paid extraction cache — the two halves are split
because the paid entries and the ledger reader do not exist until then, and a plan that pretends
otherwise is a plan with a forward reference in its code.

`pnk doctor` reports entry count, bytes, `orphans / entries`, and paid orphans separately.
**Tests:** `tests/test_extract_cache.py` — a second sync of an unchanged PDF calls the adapter
**zero** times (spy-counted); a changed document, a changed fingerprint and a truncated cache file
each miss rather than crash; two KBs holding the same PDF get two cache files;
`::test_the_sweep_spares_paid_entries` — a soft-deleted document whose entry was written by a paid
backend survives a fully successful sync and is reported, while its free twin is swept. Plus
`tests/test_sync.py::test_clear_cache_preserves_the_ledger` and
`::test_clear_cache_without_yes_and_without_a_tty_aborts`.
**Exit criteria (repo-verifiable):** the zero-call assertion; the ledger-survives assertion; the
paid-entry survives the sweep; `--clear-cache` and `--yes` in `pnk sync --help` and in §6.3's prose
in the same commit.

### I5 — PDF chunking, page provenance, and the span invariant (`schema_version` 2)

`chunk_document(kind="pdf")` consumes **I1's `ExtractedText`** — text plus `page_spans`, the same
object on a cache hit and a cache miss — and splits at page boundaries so a chunk never spans two
pages without recording both. It does not consume blocks: blocks are the free backend's internal
geometry, the cache never stored them, and the paid backend never had them. The `_fit` / `_atomise`
machinery is reused
unchanged — and its guarantees are **re-asserted for the new path, not assumed**: the token limit,
never-trim, and the overlap-must-not-breach-`max_tokens` rule that v0.1's I6 found broken.
`store.py`: `chunks.page_start` / `page_end` (INTEGER, NULL for non-paged sources), `ChunkRow` and
`Chunk.as_row()` grown together (already coupled), `SCHEMA_VERSION = 2`. `heading_path` stays
**NULL** for PDFs — a PDF has pages, not headings, and stuffing `"p. 7"` into a free-text
filter/citation column is v0.1's I6 defect rewritten.

**The fingerprint is per document, not per index.** `documents` gains `extraction_backend` and
`extraction_fingerprint` (TEXT, NULL for non-extracted sources). A single `meta` key could not
describe a corpus where `pnk sync --extract=claude-vision` ran over some documents and the free path
over others — which the CLI explicitly allows — so it would either be wrong or refuse every query on
a perfectly coherent KB after any `--extract` run. §4.4's coherence gate therefore checks **each
document against its own recorded backend**: for every distinct `(backend, fingerprint)` pair among
active documents, re-derive that backend's current fingerprint **from I1's client-free registry
inputs** and compare. Any mismatch **refuses the whole query**, naming the affected documents and
the count, with the same remedy shape as a model mismatch — partial results from a half-stale index
are the silent-garbage failure §4.4 exists to prevent.

Resolving inputs rather than importing the backend is what makes this affordable and safe. The draft
had the check re-derive the fingerprint from a method on the backend, which on a KB holding one paid
document would have imported `anthropic` **on every query** — violating the invariant I7a's gate 4
asserts, and passing CI only because that gate's run list uses a KB with no paid documents. It also
carried a false rationale for skipping: an absent `anthropic` was said to mean the extraction cannot
have changed, but claude-vision's fingerprint inputs are model id, prompt version, schema version
and request-shape version — **all package constants**. A `pinakes` upgrade that bumps the prompt
genuinely changes the extraction whether or not the SDK happens to be installed, so the skip
disabled the check on precisely the backend where staleness costs money. With inputs in the
registry the check **always runs**; the only genuine skip left is a backend name the registry does
not know at all (a KB written by a future version), which `pnk doctor` WARNs about and queries
proceed past, because a fingerprint that cannot be computed cannot be compared.

**The backend is part of the change decision, in the paid direction only** (decision 9). §6.4's
"path and hash unchanged → skip" was the only re-processing trigger, so two silent failures followed
from I6b's hook rule and I4's cache respectively: a scanned PDF committed while hooks force
`--extract=pypdfium2` is indexed as empty and then **skipped forever** by every later manual sync,
on a KB whose manifest asks for the paid backend; and `--rebuild` re-extracts a paid document with
whatever the manifest says, missing the paid cache entry and overwriting it with pypdfium2's empty
output. §4.4 cannot see either, because each document still matches *its own recorded backend* —
which is now the free one. Both are the silent quality loss §9 names as this release's reason to
exist. The rule:

- A document whose recorded backend is **free** and whose effective backend for this run is **paid**
  is stale: it is re-extracted, subject to every cap and confirmation.
- A document whose recorded backend is **paid** and whose effective backend is **free** is **never**
  re-extracted. Not by a hook, not by `--rebuild`, not by `--extract=pypdfium2`. The existing
  extraction stands and the run says so once. Only `--force` with an explicit free `--extract`
  overwrites it, and it prints what it is discarding first.
- `pnk doctor` lists both gaps by path: documents awaiting a paid extraction, and documents whose
  paid extraction the manifest no longer asks for.
**Tests:** `tests/test_chunk_pdf.py` — **the span invariant over all 19 fixtures and every chunk**
(`chunk.text == extracted.text[char_start:char_end]`); every character of the extraction lands in ≥1
chunk (v0.1's never-drop guarantee, re-proved here); page numbers monotonic and within
`1..page_count`; a two-page chunk recording both; `heading_path is None` for every PDF chunk.
`tests/test_store.py` — schema version 2, and a version-1 index refusing to open naming `pnk sync
--rebuild`. `tests/test_search.py::test_a_changed_extraction_fingerprint_refuses_the_query` — a
mixed-backend index where every document matches its own backend queries fine; mutating one
document's stored fingerprint refuses with the remedy and names that document; an **unknown**
backend name WARNs in doctor and does not refuse; and `::test_coherence_never_imports_a_paid_client`
— a query over a KB holding a paid document, run in a fresh subprocess, asserting `"anthropic" not
in sys.modules` (the case I7a's gate 4 does not cover).
`tests/test_sync.py::test_backend_drift` — a free-indexed PDF re-extracted by a paid run; a
paid-indexed PDF **not** re-extracted by a hook-style free run, by `--rebuild`, or by
`--extract=pypdfium2`; `--force` overwriting it only after printing what it discards.
**Exit criteria (repo-verifiable):** the invariant holds corpus-wide; `SCHEMA_VERSION == 2`; a v0.1
index raises `IndexSchemaError` with the rebuild remedy; the mixed-corpus coherence test passes; the
coherence check imports no paid client; the four backend-drift cases pass; §6.4 amended and the
CHANGELOG entry states the forced rebuild in the same commit.

### I6a — Budget core, pure (rule 11: the pure half of the money machinery)

`src/pinakes/budget/`, with **no I/O and no `anthropic` import**. `prices.toml` ships in the wheel
like the templates, carrying `as_of` as `YYYYMMDD HH:MM`, per-model `input_per_mtok_usd` /
`output_per_mtok_usd`, the cache-write (1.25×) and cache-read (0.10×) multipliers, and — because the
manifest prices in EUR and the vendor in USD — a `usd_per_eur` rate carrying the **same** `as_of`.
Seeded from the current table: `claude-opus-5` at $5.00 / $25.00 per MTok.

**`estimate.py` estimates over *requests*, and a request is a K-page slice** (decision 8). Getting
the unit wrong is the difference between a reservation that bounds a run and one that is wrong by an
order of magnitude — in either direction. Pass 1 corrected a per-*page* estimate that under-reserved
against whole-document requests; pass 2 then showed the whole-document request shape is itself the
defect, because it makes input quadratic and stops fitting the context window. Sending each page
exactly once restores the linear model pass 1 was right to reject only because the request shape
made it false.

So: **worst case per request = `K × page_tokens × input_price + max_tokens × output_price`**, and a
document is `ceil(N / K)` requests. There is no cache multiplier in it because there is no
`cache_control` marker: consecutive slices share no prefix, so a cache write would cost 1.25× to
prime something the next request cannot read. The output bound is `max_tokens` — the request's hard
output ceiling, which on `claude-opus-5` caps thinking and response text *together*, so it is the
correct and only safe bound. Reconciliation folds the response's true `usage` (`input_tokens`,
`output_tokens`) back in and returns the difference to the running total.

**A context-window pre-check is part of the estimate, not an afterthought.** `K × page_tokens` plus
the prompt must fit the model's documented maximum input — 1M tokens on `claude-opus-5`. At K = 5
and the conservative 6,000-token page constant that is 30K, so it never fires in practice; it exists
because its absence is precisely what made the draft's design unimplementable at 166 pages while its
only size check tested a 600-page API limit that would never be reached. A check that cannot fire
under the shipped constants but names the exact limit that bounds them is cheap; discovering the
bound from a 400 at page 150 of a paid run is not.

**Worked example, the case the draft could not serve.** A 200-page scan at the conservative constant
is 40 requests: input `200 × 6,000 = 1.2M` tokens at $5/MTok = **$6.00**; output reserved
`40 × 8,000 = 320K` at $25/MTok = **$8.00**; **$14.00 reserved**, and reconciliation typically
returns most of the output half. The same document under the draft's shape did not fit in the
context window at all, and at 100 pages reserved ~$375 — a number no cap in this plan can approve,
so the feature would have failed closed with a refusal no user could satisfy.

**K = 5, and it is a semantic constant, not a tuning knob.** Output per request is then ~4,000
tokens against a `max_tokens` of 8,000 — 2× headroom, so truncation is rare and a truncation retry
re-asks five pages rather than twenty. Larger K needs a proportionally larger `max_tokens`, which
raises every reservation and makes each retry more expensive; K = 1 sends each page with no
neighbours, which loses a table or sentence continuing across a page break — the thing slicing at a
5-page boundary keeps in the common case. **K is hashed into the request-shape version** (I7b),
because the context a page is transcribed with is part of what produced its text: changing K is a
cache miss and a coherence refusal, not a silent re-tuning.

The per-page token constant is **measured**, not guessed, with `measured_on` recorded beside it.
Until that measurement (human-gated, I7b) it uses a documented conservative ceiling of **6,000 input
tokens per PDF page**, derived from the vendor's own documented high-resolution page budget (up to
~4,784 visual tokens for a rendered page, plus that page's text) — a per-page number applied to the
*actual* page count, never the API's 600-page maximum. The estimate ships its denominator as
`pages_estimated N of M`.

**Money is `Decimal` end to end, quantised once.** Every euro and dollar amount is `Decimal`;
`prices.toml`'s values parse as `Decimal`, not `float`. Quantisation to cents happens at exactly one
point — when a reservation or a reconciliation is **written to the ledger** — and comparisons
against caps are `<=` on the quantised value, so `spent + reserved == cap` proceeds and one cent
more does not. Stating this matters because the boundary tests assert exact equality: over floats
those tests are flaky, and a cap that is off by a representation error is not a hard cap.

`reserve.py` is the §5 accountant, and it is pure: `reserve(estimate, caps, spent) -> Decision`,
where `spent` is a `WindowTotals(operation, day, month)` the caller supplies. **Before every call it
checks all three ceilings** — `per_operation_eur`, the new `daily_eur`, and `monthly_eur` — and if
any of `spent.X + reserved` exceeds its cap the call is **never made**. The refusal names which
window blocked it and by how much. One operation being one `pnk sync` bounds a single invocation
only; the day and month windows are what stop a sequence of invocations, which is the failure mode
a hook-driven KB actually has.

`window.py` aggregates an in-memory list of ledger records by day/month in `[budget] timezone`;
reading the file is I6b's job, which is what keeps this half pure. `[budget]` gains
`max_price_age_days` (default 30) — an estimate against older prices is refused, not silently wrong
— and `daily_eur` (default 1.00, between the 0.05 per-operation cap and the 5.00 monthly one: a
burst limiter, where monthly is the real ceiling).

**How a reservation/reconciliation pair aggregates — the rule the draft never stated.** Every call
writes two ledger lines (I6b), and until this is pinned down the same ledger supports three
different totals: summing both lines double-counts every call and refuses at half the real cap;
counting only reconciliations makes an in-flight reservation invisible, so the cap is not a cap; and
counting reconciliations plus unreconciled reservations breaks at a window edge. The rule:

- **A pair is one record, attributed to the *reservation's* timestamp.** A call reserved at 23:59:58
  and reconciled at 00:00:03 belongs entirely to the first day. Attribution never moves.
- **The reconciliation supersedes the reservation's amount in place** — it does not add to it.
- **An unreconciled reservation counts at its reserved amount**, so an in-flight or crashed call
  consumes headroom rather than vanishing. It is reported as `unknown outcome`, never as zero.
- **A `void` record (I7b) closes a reservation at zero** — the escape hatch for a call that never
  billed, without which a handful of transient failures would permanently consume a month's budget.

Which reading applies is not academic: with the shipped €5.00 monthly default, counting reserved
amounts buys roughly a fifth of what counting reconciled actuals buys.

**The default caps refuse the paid extractor, and that is correct — but the refusal has to say so
completely.** One 5-page request at `max_tokens = 8000` reserves `30,000 × $5/MTok` input plus
`8,000 × $25/MTok` output = **$0.35**, which converts through `prices.toml`'s own `usd_per_eur` (a
bare euro figure here would be exactly the unprovenanced number I6b's ledger rule exists to
prevent). That is well past the €0.05 `per_operation_eur` default, which was sized for one
`pnk ask --deep` question. Raising it alone is **not sufficient** for any real document: `daily_eur`
binds next, then `monthly_eur`, and a refusal naming one cap at a time walks the user through three
sequential manifest edits to discover that. So the refusal prints **all three windows with their
current headroom**, the computed estimate, the complete manifest edit that would admit this run, and
one line stating the ongoing exposure that edit creates — because `--extract=claude-vision` is a
per-run override while a raised cap is permanent, and nothing in the draft acknowledged the
asymmetry. The plan does not lower `max_tokens` to sneak under a default that was never meant to
cover a 200-page document.

**Tests:** `tests/test_budget_core.py`, table-driven — the exact cap boundary for **each** of the
three windows (`spent + reserved == cap` proceeds; one cent more does not, asserted over `Decimal`),
and a case where the operation cap passes but the month's does not;
`test_reservation_bounds_every_usage_table` — hand-written `usage` records asserting the reservation
is never below the reconciled actual; `test_a_pair_straddling_midnight_is_attributed_to_the_start`
and its month-end and DST twins, in a non-UTC timezone — the aggregation that *produces*
`WindowTotals`, which the draft tested only downstream of a caller-supplied value;
`test_a_void_closes_a_reservation_at_zero`; `test_the_refusal_names_all_three_windows`; confirm
threshold and hard cap staying independent, so confirming at the cap value is reachable (DESIGN pass
3's finding); a stale `as_of` refusing to estimate and naming the remedy; a malformed `prices.toml`
as a startup error, not a silent zero; `test_the_context_window_precheck_names_its_limit`.
**Exit criteria (repo-verifiable):** the boundary tests for all three windows; the four
window-attribution tests; an import-graph test asserting `budget/` imports neither `anthropic` nor
anything under `extract/`; a `check.sh` gate parsing `prices.toml` and failing if `as_of` is missing
or unparseable; DESIGN §5's two rows and §2.1's `[budget]` row amended in this commit.
**Deliberately not a CI gate:** price *staleness* — a wall-clock gate fails the build on a quiet
weekend with no code change, so staleness is a `pnk doctor` WARN and a runtime refusal, where it
protects a user instead.

### I6b — Budget I/O: the ledger, the prompt, `pnk budget`, and hooks that cannot spend

`budget/ledger.py` appends to `.pinakes/ledger.jsonl`; each line is a single sub-4KB `O_APPEND`
write, atomic on POSIX (§5). **The ledger stores no query text and no document content** —
timestamp, `operation_id`, `call_id`, record kind, operation kind, model, token counts, cost, KB id,
nothing more — and a test asserts it by running a paid extraction from a recorded fixture whose page
text contains a unique sentinel and grepping the whole ledger for it.

**Two identifiers, because the draft used one word for two things.** `operation_id` is one `pnk
sync` invocation — the unit `per_operation_eur` bounds. `call_id` is one API call — the unit a
reservation/reconciliation pair keys on, and what I4's cache entries join against. Collapsing them
made `per_operation_eur` ambiguous between "one sync" and "one call" in a section where the
difference is a factor of forty.

**Cost is recorded in USD with its conversion provenance, never as a bare number.** Each line
carries `cost_usd`, the `usd_per_eur` rate used, and the price table's `as_of`. EUR is computed at
read time. A ledger line that says only `cost: 0.043` is unreadable a month later — nobody can tell
which currency it is or which rate produced it — and the rate is exactly the number that drifts.
`pnk budget` shows, per window, which rate and which `as_of` its totals were computed with, and
flags a window that spans more than one rate.

**Three record kinds, keyed by `call_id`.** A **reservation** written *before* the call, then
exactly one of a **reconciliation** (the call returned; true `usage` supersedes the reserved amount
in place) or a **void** (the call never billed — cost zero, closing the reservation). That is the
durability answer (rule 12): a crash between the call and the ledger write would otherwise lose
spend history permanently, the one thing in `.pinakes/` that cannot be recomputed, and a reservation
with neither successor is reported as `unknown outcome`, not dropped and not counted as zero.

The `void` kind is what makes the protocol survivable. Without it, every call that *raises* —
timeout, 429, 5xx, an oversize 400 — leaves a reservation nothing ever closes, and I6a's rule counts
an unreconciled reservation at its reserved amount. `ledger.jsonl` is append-only and CLAUDE.md
forbids editing it, so that phantom spend is permanent: a handful of transient failures would lock a
user out of their monthly budget with no way back short of a new month. Voids are written from a
`finally` path, so an interrupted process still degrades to a *visible* `unknown outcome` rather
than a permanent phantom charge. Reading the ledger into I6a's `WindowTotals`, under I6a's
attribution rule, is this module's job; the wiring is tested, not assumed.

`confirm_above_eur` prompts on a TTY. **When a confirmation is due and there is neither a TTY nor an
explicit `--yes`, the run aborts** — the scope matters: read broadly this would abort every
non-interactive sync, which is the shape of the pass-1 finding it was written to fix, so the abort
fires only when a confirmation is actually owed. `--yes` (required for cron) says in `--help` what
it authorises: it answers the confirmation prompt and `--clear-cache`'s confirmation, and **raises
no cap**.

**Hooks and CI cannot spend.** DESIGN §6.3 makes `pnk sync` machine-driven — `pre-commit`,
`post-commit`, `post-merge`, and the workflow `pnk init --ci` writes. All four are non-interactive,
so on a KB configured for `claude-vision` the no-TTY abort above would kill hook-driven freshness on
every single commit, and a `--yes` in a hook would spend afresh on every commit with a fresh
per-operation allowance each time. Resolution: `pnk install-hooks` and `pnk init --ci` write
`pnk sync --extract=pypdfium2` **explicitly** (the flag exists from I1, so a hook written here is
runnable here), forcing the free backend regardless of the manifest, print one line saying so at
write time, and carry the same line as a comment in the generated hook. A machine-driven sync
therefore indexes a scanned PDF's (empty) free extraction and records it honestly — **and
recoverably**, because I5's backend-drift rule makes that document stale until a paid run picks it
up, rather than skipped forever on a content hash that never changes again. Paid extraction stays a
deliberate human invocation. `pnk doctor` reports the combination (paid backend configured, hooks
installed and forcing the free one, N documents awaiting paid extraction) so the split is visible
rather than surprising. `make budget` wraps `pnk budget` and is created **here**, by this increment
— I9 only documents it.

`pnk budget` shows spend by day/month/operation with `reservations N, reconciled M, voided V,
unknown K`; `pnk doctor` gains a price-table check: OK, or WARN past `max_price_age_days` naming the
file.
**Tests:** `tests/test_ledger.py` — the sentinel test; a process killed between reservation and
reconciliation leaving a readable ledger and an `unknown outcome` row; a call that raises leaving a
`void` and **no** lasting headroom consumption; concurrent appends from two processes interleaving
no record; `--rebuild` and `--clear-cache` both leaving the ledger byte-identical; every line
carries `cost_usd`, `usd_per_eur` and `as_of`.
`tests/test_cli_budget.py` — `pnk budget` on an empty ledger printing zeros rather than a traceback;
totals on a mixed ledger matching a hand-computed fixture, including a window spanning two
`usd_per_eur` rates; a confirmation due with no TTY and no `--yes` exiting non-zero with a remedy,
**and a non-interactive run with nothing to confirm proceeding normally** — the two halves of L-6's
ambiguity, one test each; **a KB whose ledger already holds €4.99 of a €5.00 month refuses the next
call even though the operation cap is untouched** — the seam between I6a's arithmetic and I6b's
ledger read, proved rather than assumed.
`tests/test_hooks.py` — `::test_hooks_force_the_free_backend` **executes** each generated hook
against a KB configured for `claude-vision` and asserts the sync ran with the free backend and spent
nothing (spy-counted). Asserting the string `--extract=pypdfium2` is *present* is the
string-assertion failure the ground rules exist to prevent: it passes on a hook that never runs. A
second, cheaper test keeps the grep as a readability check on all three hooks and the CI workflow.
**Exit criteria (repo-verifiable):** all of the above; §5 amended to say the machinery ships in v0.2
with all three windows enforced, and §8's v0.4 row updated in the same commit.

### I7a — The paid-path allowlist gate and the invariant amendments (lands first)

**No paid code exists yet, and that is the point.** v0.1's paid-API grep gate never shipped because
it was promised in a section with no owner (rule 8); a gate that arrives in the same increment as
the thing it guards has never once refused that thing. So the gate lands before `extract/claude.py`
exists, and its first job is to prove it fails on a planted violation.

Today `.github/workflows/ci.yml` fails if `anthropic` is imported anywhere under `src/`. The new
gate: one file, `.paid-path-allowlist` at the repo root, lists the permitted paths — exactly
`src/pinakes/extract/claude.py` at v0.2 — and **`check.sh`, CI and the test all read that one
file**, so three copies cannot drift.

- **Gate 1:** every listed path must exist, so a stale entry cannot rot unnoticed. At I7a the listed
  path does not exist yet, so I7a ships the allowlist **empty** and I7b adds the single line in the
  same commit that creates the module — which is itself the gate working.
- **Gate 2:** the paid-client grep (`anthropic|openai|cohere|mistralai|google\.generativeai`) runs
  over `src/` **excluding** the listed paths; any hit is a hard failure with the existing message.
  **It gets a negative test too.** The part most likely to be wrong is the path exclusion itself: an
  entry of `src/pinakes/extract/claude.py` implemented as a prefix or substring match would silently
  exempt a whole directory, and gate 1 (the paths exist) cannot see that. So a test plants an import
  in a **non**-allowlisted module and asserts gate 2 fails. This increment's own principle — "a gate
  only ever observed passing is a gate nobody has tested" — applies to every gate in it, not only to
  the one the draft happened to test.
- **Gate 3:** `anthropic` must not appear in `[project.dependencies]` (I1's gate, reused).
- **Gate 4, the one that actually matters,** is a test rather than a grep: after a full free-path
  run — `pnk sync`, `pnk search`, `pnk doctor`, `pnk budget`, and an MCP handshake — `"anthropic"

  1. **It runs in a fresh subprocess** (`uv run python -c …`) which prints its sorted `sys.modules`

     the same shape as v0.1's `-wal` test, which was correct and then defeated by an environmental

  2. **It skips with a printed reason when `anthropic` is not installed**, because with the package

  3. **A negative test proves it in the other direction**: the same subprocess is run with an

### I7b — The paid Claude-vision extractor: request shape, validation, retries

`src/pinakes/extract/claude.py` — **the only module in `src/` permitted to import `anthropic`**, and
the line I7a's allowlist gains in this commit. Registered as backend `claude-vision`, reached only
when the manifest says so or `pnk sync --extract=claude-vision` is passed. Every free step precedes
every paid one:

1. **Local pre-checks, zero cost** (PDFScout): page count, encryption detection, per-request size
   against the documented limits (32 MB per request; 600 pages, 100 for 200k-context models) **and
   against the model's context window** via I6a's pre-check, and the free extractor's own text yield
   against **I3b's fitted floor** — if the free path already clears it, the paid path **refuses to
   spend** unless `--force`, and says so. Paying to re-extract a healthy PDF is the most likely way
   a user loses money by accident. **With no fitted text-yield floor installed, this step refuses to
   spend at all** rather than proceeding without its guard (I3b). 2. **Estimate and reserve**
   through I6a, **before every single call**: the first attempt, every schema retry, the refusal
   retry, the truncation retry, and I7c's audit re-extraction each take their own pre-call
   reservation and their own ledger pair keyed by `call_id`. §5 requires reserving before *each*
   call, and a single reservation covering a slice loop is not a cap. The real per-slice ceiling is
   **7 calls** — one first attempt, up to three schema retries, one refusal retry, one truncation
   retry, one audit re-extraction — and it is **enforced as a constant**, not left to emerge from
   the branches, so the bound is structural rather than incidental. (The draft asserted "up to four
   calls per page" two lines after enumerating five; the number was load-bearing in the risk table
   and wrong in both places.) The client is constructed as **`Anthropic(max_retries=0)`**: the SDK's
   default of 2 silently turns one `messages.create` into up to three billed HTTP requests — and a
   request retried after a timeout can be billed twice for generation the server already completed —
   so the accountant, not the SDK, owns retry. 3. **Failure handling for calls that never return a
   response.** Steps 4's branches cover HTTP 200s; this covers everything else, and without it the
   reservation written in step 2 is never closed. Any non-response outcome writes a **`void`**
   ledger record (I6b) from a `finally` path, releasing the reservation at zero. Then: **429 and
   5xx** are retried with bounded exponential backoff, at most twice, each attempt taking a
   **fresh** reservation — the accountant owns the retry the SDK is no longer doing. **Timeouts**
   are treated as billable-unknown: no automatic retry, the reservation is left as `unknown outcome`
   rather than voided, because the server may have completed generation, and the page is recorded as
   failed. **4xx other than 429** is a page failure with the API's message; it is deterministic, so
   retrying it only spends again. 4. **Request shape — a K-page slice, not the whole document**
   (decision 8). `pdfium.slice_pages` writes a K = 5-page sub-document; it goes in a `document`
   content block placed **before** the text block — `{"type": "document", "source": {"type":
   "base64", "media_type": "application/pdf", "data": …}}`, newline-free base64, no beta header.
   **No `cache_control` marker**: consecutive slices share no prefix, so a cache write would pay a
   1.25× premium to prime something the next request cannot read. Structured output via
   `output_config: {"format": {"type": "json_schema", "schema": …}, "effort": "low"}` — the current
   parameter, not the deprecated top-level `output_format`, and the reason citations are unavailable
   (they 400 together). The schema is an array of per-page objects, so the response maps to pages
   positionally and a slice that returns the wrong page count is a schema failure rather than a
   silent misalignment. Thinking is **explicitly** `{"type": "disabled"}`: per-page transcription is
   not a reasoning task, thinking bills at the output rate, and `max_tokens` caps thinking and
   response together so an un-budgeted thinking phase would truncate the JSON body and burn paid
   retries. `claude-opus-5` accepts disabled thinking **only at effort `high` or below**, so the
   pair is pinned together as module constants. Of the two documented disabled-thinking failure
   modes, one is genuinely structural and one is not: tool-call-as-text cannot occur, because no
   tools are declared. But `output_config.format` constrains the response's **structure**, not its
   **string content** — a `<thinking>` fragment can land *inside* a page-text field and be cached,
   chunked and cited as extracted text. The draft claimed it "cannot reach the body", which is
   false. So the prompt carries the vendor's recommended generic instruction — *do not include
   internal or system XML tags in the response*, deliberately generic, because naming thinking tags
   specifically is measurably less effective — and the prompt carries **no**
   don't-think/don't-reason instruction, which increases leakage. A **tag-leaking recorded fixture**
   proves the handling, because "checked rather than assumed" with no test behind it is assumed. The
   escape hatch, if the human-gated run shows otherwise, is adaptive thinking at `low` effort with
   `max_tokens` raised to budget for it — and the reservation follows automatically, because its
   output bound is `max_tokens`. `max_tokens` is **8000**, ~2× the ~4,000 tokens five pages of prose
   produce. `temperature`, `top_p` and `top_k` are never sent: they 400 on this model.
   `response.model` — the snapshot that actually answered, which the requested alias `claude-opus-5`
   does not name — is recorded per slice in the cache entry's `per_page_provenance`; it is free to
   store, and the "checked and declined" note on server-side fallbacks says in as many words that a
   fingerprint which cannot record the answering model is the reason that feature is off. 5.
   **Per-page validation with ≤3 retries** (PDFScout), branching in this order: `stop_reason ==
   "refusal"` is checked **before reading `content`**, counts as a page failure, is retried once and
   then recorded — and it is the *cheap* failure, because a pre-output refusal is not billed at all.
   `stop_reason == "model_context_window_exceeded"` is a **hard** failure naming the slice and the
   computed token count: at K = 5 it should be unreachable, so reaching it means the page constant
   is wrong, and retrying an identical oversize request only spends again. `stop_reason ==
   "max_tokens"` is checked **next, before schema validation**: a truncated response is invalid
   JSON, and without this branch it would be retried identically three times, all paid, all
   truncating at the same place. A truncated slice is re-asked **once** at `max_tokens = 16000`
   under a fresh reservation (the output bound doubled, so the old one no longer bounds it); a
   second truncation records a failure naming the pages. **A retry re-asks the whole slice, never a
   single page from it**: a page transcribed with different neighbours is a different extraction,
   and mixing the two inside one document is the provenance mess the fingerprint exists to prevent.
   The plan does **not** split a page: the sub-page boundary has no ground truth in the corpus, so a
   split would produce text nothing can score. 6. **Assembly bypasses `layout.py`** (decision 10).
   The response is per-page text with no coordinates, so `blocks_from_chars`, `reading_order` and
   `strip_running_heads` have nothing to operate on; fabricating geometry to feed them would be
   invented data driving a stage that reasons about position. This backend builds `ExtractedText`
   directly from the per-page strings, applying only `normalise()` — which is a pure string function
   and needs no geometry. The consequence is real and is **measured, not waved away**: running-head
   handling and reading order differ between a free and a paid extraction of the same page, and I3b
   scores both pipelines over the scanned stratum's text-layer twins and records the delta. 7. **The
   fingerprint.** `claude-vision`'s inputs, declared in I1's client-free registry entry, are
   `(backend name, model id, prompt version, schema version, request-shape version — which includes
   K, pypdfium2 version, pdfium build)`. It includes the pdfium versions because this backend
   **does** load pypdfium2 — to slice, to pre-check the free text yield, and for I7c's audit, whose
   output decides which pages are re-extracted and therefore what text the run finally produces. The
   draft omitted them on the stated grounds that "this backend never loads" pypdfium2, which its own
   steps 1 and 6 contradict. It **excludes `LAYOUT_VERSION`**, because this backend does not run
   `layout.py` (decision 10) and a free-path constant must not be able to invalidate paid cache
   entries. It **excludes `max_tokens`**, a budget knob rather than a semantic one — a slice
   re-asked at a higher cap yields *more complete* text of the same kind, and hashing it would
   change the fingerprint mid-run at exactly step 5's retry. Changing `[extraction] model` or K
   produces a cache **miss** and, on an already-built index, a §4.4 coherence **refusal**. 8.
   **`--estimate-only`.** Builds the real request for the first slice and calls

   measurement below. **It is a network call, not an offline estimate** — stated in `--help`, in
   §6.3 and here, because "estimate" reads as free and this one requires a key. It is never
   *required*: the estimate must exist on an install with no client at all.

### I7c — The completeness audit, staging, and all-or-nothing commit

1. **Completeness audit** via I3b's `word_coverage` against pypdfium2's native layer. Pages below
   **I3b's fitted floor** are re-extracted once, and that re-extraction is itself reserved and
   ledgered like any other call. Pages with no usable native layer (the scanned stratum) are
   **exempt and reported as exempt**, with their denominator: `audited N of M, exempt K of M`.
   **With no fitted floor in `baseline.json`, no re-extraction is triggered at all** — coverage is
   still reported, but a threshold with no provenance does not get to spend money (I3b).
2. **Staging and commit.** Each validated page is written to
   `cache/extract/partial/<hash>-<fingerprint>/<page>.json` (temp + `os.replace`) as it completes,
   so an interrupted 200-page run does not re-pay for pages already extracted. Under decision 8 the
   resume is **genuinely free of re-payment for staged pages**: each request carries only its own
   slice, so there is no prompt cache to re-prime and no 1.25× write to re-pay — the draft's honest
   caveat about a 5-minute TTL simply no longer applies. Resume granularity is the **slice**: a
   slice interrupted mid-flight is re-asked whole, because its pages were transcribed together.
   Only when every page passes is the single complete cache entry written and the staging directory
   removed. A partially extracted document writes **no** complete entry and goes to `failures`;
   `on_exceed = "partial"` is honoured at the corpus level (completed documents keep their entries,
   the run stops cleanly), never at the page level — a half-extracted document in the index is the
   silent truncation §4.6 exists to prevent. **DESIGN §5 gains that definition in this commit**: it
   is a rule about what `partial` means, and §5's existing amendment row covers only the opening
   sentence and the control table.
3. **`--clear-cache` learns what it is destroying.** Its printed summary (I4) gains the euros the
   cached entries cost, joined from the ledger on the entry's `call_ids` (I4) — the draft said "by
   operation id", which no cache entry recorded and no ledger line could be matched to, so the
   behaviour its verification row asserts was unimplementable as specified. CLAUDE.md's
   "**`.pinakes/` is disposable except `ledger.jsonl`**" invariant is amended in this commit to
   except the paid extraction cache too: those entries are derived state that costs real money to
   derive, which is a different thing from disposable. I4's automatic eviction already spares them,
   so the invariant and the sweep agree rather than contradicting each other.
4. **Flag scope, stated once and in `--help`.** The complete list, so none of them can arrive
   without a stated scope again: `--extract=BACKEND` (I1) overrides `[extraction] backend` for one
   run. `--estimate-only` (I7b) measures and exits, **and makes a network call**. `--yes` (I4)
   answers confirmation prompts (`confirm_above_eur`, `--clear-cache`) and raises no cap.
   `--clear-cache` (I4) empties the extraction cache after confirming. `--force` bypasses **exactly
   two things**, both of them refusals to spend that a user may legitimately overrule: step 1's
   refusal to pay for a PDF whose free text yield is already healthy, and I5's refusal to let a free
   run overwrite a paid extraction. It never bypasses `per_operation_eur`, `daily_eur`,
   `monthly_eur`, the stale-price refusal, the missing-floor refusal, or the no-TTY abort — a flag
   that can widen a hard cap is not a hard cap.

## Durability sweep (rule 12)

*Which writes lose unrecoverable information if interrupted?*

- **`ledger.jsonl` — the only genuinely unrecoverable write, and it is new.** A crash between the
  API returning and the ledger append loses spend history permanently: money left the account and
  nothing records it. Answered by I6b's reservation → reconciliation-or-void protocol — a torn write
  degrades to a *visible* `unknown outcome`, never to a silent zero, and a call that never billed is
  closed at zero rather than consuming a month's headroom for good.
- **Paid staging entries — recoverable, but only at cost.** Regenerable in principle, and that
  regeneration is exactly what the user is paying for; written per page, atomically, consumed on
  resume (I7c). Without them an interrupted 200-page run re-pays for everything. **With them and
  decision 8's slicing, a resume re-pays for nothing already staged** — each request carries only
  its own slice, so there is no vendor-side cache to re-prime; the only re-payment is the slice that
  was in flight.
- **Free cache entries — recoverable and free. Paid cache entries are not.** Both are atomic: a
  half-written JSON that happens to parse is worse than a miss. **The eviction sweep** is the only
  new delete — derived state only, only after a fully successful sync, guarded and tested (I4) —
  and it **skips paid entries entirely**, because "derived" and "free to re-derive" are different
  properties and only the second one licenses a silent delete.
- **Sidecars for PDFs — unchanged and already atomic** (v0.1 I5, rename-based). Re-asserted rather
  than assumed: the ULID a sidecar carries is still the one thing no later command can recompute.
- **The `-wal`/`-shm` lesson (v0.1 I8b) transfers:** cache and staging are *sets* of files under
  directories, so `--clear-cache` and the sweep are tested by listing the directory afterwards,
  never by trusting that one `unlink` was enough.

## Risks specific to this sequencing

Aimed at **machinery**, deliberately: v0.1's risk table enumerated algorithmic risk, and all seven
of its HIGH findings came from areas it never contemplated — durability, file naming, boundary
arithmetic, vacuous metrics, and the gate itself.

| Risk | Why it is machinery | Mitigation |
|---|---|---|
| **Unbounded spend across invocations.** One `pnk sync` is capped; nothing caps the tenth one. Hook-driven freshness makes `pnk sync` machine-driven, so a per-invocation cap is an allowance renewed on every commit | the cap is arithmetic across a *running* total, and per-invocation framing hides that the invocations are the loop | `reserve.py` checks `per_operation_eur`, `daily_eur` **and** `monthly_eur` before every call, computed from the ledger in `[budget] timezone` (I6a boundary tests, I6b's wiring test); the three hooks and `pnk init --ci` force the free backend and say so; no-TTY aborts without `--yes`; the free path is checked first and refuses to pay for a healthy PDF |
| **Retries spend outside the reservation** | one reservation before a loop that makes up to **seven** calls per slice is not a cap, and the SDK's own `max_retries=2` turns one call into three billed requests invisibly | every call — first attempt, up to three schema retries, refusal retry, truncation retry, audit re-extraction — takes its own pre-call reservation and ledger pair, spy-asserted; the 7-call ceiling is an enforced constant, not an emergent property of the branches; the client is pinned to `Anthropic(max_retries=0)` so the accountant owns retry |
| **A call that never returns leaves permanent phantom spend** | the ledger is append-only and an unreconciled reservation counts at its reserved amount, so timeouts and 5xxs would consume a month's budget for money that never left the account, irreversibly | a third record kind, `void`, written from a `finally` path closes the reservation at zero; 429/5xx retry under a *fresh* reservation; a timeout stays `unknown outcome` because the server may have generated; tested per branch |
| **The reservation is sized on the wrong unit** | per-page input looked wrong against whole-document requests (pass 1) and the whole-document request shape was itself wrong (pass 2) — quadratic in input, and past the context window at ~166 pages | the request unit is a K-page slice, so input is linear and each page is sent once; the estimate is `K × page_tokens × input + max_tokens × output` with no cache multiplier, because there is no cache marker; a context-window pre-check names the limit that bounds it |
| **The cache key is right and the cache *path* is wrong** | the I8b shape: correlated filenames, correctness argued about one of them | the cache lives under each KB's own `.pinakes/`; a test syncs two KBs holding the same PDF and asserts two files; staging is keyed by the same pair plus page |
| **The fingerprint hashes the wrong things — in either direction** | hashing too little serves old-model text from the cache and blinds the coherence gate; hashing too much makes a free-path refactor invalidate every paid entry and refuse every query until the user pays to re-extract — a constant that can send an invoice | per-backend **inputs**, declared in a client-free registry entry so the check never imports a paid client; `claude-vision` hashes model id, prompt, schema, request shape (including K) and the pdfium versions it genuinely uses, and **excludes** `LAYOUT_VERSION`, which it never runs; tests assert that changing `[extraction] model` or K both misses the cache and refuses the query |
| **The backend is not part of the change decision** | §6.4 keys re-processing on path and content hash alone, so a document indexed by the wrong backend is skipped forever — its hash will never change again | the recorded `extraction_backend` joins the decision, in the paid direction only: a paid run re-extracts what a free one indexed; a free run, `--rebuild` and a free `--extract` never overwrite a paid extraction; `pnk doctor` lists both gaps; four named cases in `test_backend_drift` |
| **Partial or interrupted extraction leaves a document half in the index** | a truncated document is exactly the silent quality loss §4.6 exists to prevent, and nothing in the output reveals it | all-or-nothing commit: no complete cache entry until every page passes, and the document goes to `failures`; `on_exceed = "partial"` is corpus-level only, stated in `--help` and §5 |
| **The paid-path allowlist erodes, or its decisive gate is inert** | a one-line import in a new module quietly makes the free path paid; and a behavioural gate that asserts a package is absent is vacuously true wherever that package is not installed | one `.paid-path-allowlist` read by `check.sh`, CI and the test; the gate lands before the code it guards; it runs in a fresh subprocess, skips loudly where it cannot be meaningful, is exercised on a `[light,pdf,claude]` CI leg, and has a negative test that plants an import and asserts it fails |
| **Scanned-PDF quality cannot be measured by the audit that measures everything else** | the completeness audit's witness is the native text layer, and a scanned page has none — the gate is blind on precisely the stratum the feature exists for | the audit reports `exempt K of M` rather than scoring exempt pages as passing; the scanned stratum's ground truth is hand-authored from the generator's spec; its numbers land in §9 with date, model and cost, labelled as measured on synthetic rasters |
| **Price-table staleness, and the USD→EUR rate inside it** | the manifest prices in EUR and the vendor in USD; the rate is a second number that goes stale with nothing saying so, and a ledger that records only a EUR figure cannot be re-derived later | `usd_per_eur` carries the same `as_of` as the prices; every ledger line records `cost_usd`, the rate and the `as_of`, and EUR is computed at read time; `pnk budget` shows which rate each window used; `pnk doctor` WARNs past `max_price_age_days`; an estimate against stale data refuses rather than guessing. Not a CI gate — see I6a |
| **A threshold that spends money is chosen by intuition, fitted on the wrong pair, or never ships** | `word_coverage`'s floor triggers paid re-extraction and the text-yield floor stops it, so a guessed value is a guessed invoice — and a floor fitted against ground truth but applied against the native layer is a different distribution wearing the same name, while a floor living only in `tests/` reaches no installed user at all | both fitted in I3b on the I2 corpus, `word_coverage` **on the same pair it is applied to** and with that pair named in `baseline.json`, the scanned stratum as the exempt control, committed with `fitted_on`; both shipped as package data in `floors.toml` and read through `importlib.resources` in the test; absent either floor, its own consumer refuses to spend |
| **The paid path leaks the model's internal text into the corpus** | `output_config.format` constrains structure, not string content, so a `<thinking>` fragment inside a page-text field is cached, chunked and cited as extracted text — and the draft asserted this "cannot" happen | the prompt carries the vendor's recommended generic no-internal-XML-tags instruction and **no** don't-reason instruction, which increases leakage; a tag-leaking recorded fixture proves the handling rather than asserting it |
| **The recorded-fixture harness diverges from the real API** | a fake that encodes only the happy path proves nothing about retries, refusals or truncation | fixtures include a refusal, a schema-invalid page, a truncated page and a page that drops content; the one human-gated real-API run at I7b is the reconciliation, and its date and model are recorded |
| pypdfium2 or anthropic warns at import, and `filterwarnings = ["error"]` turns a whole matrix leg red | a pyproject setting colliding with a dependency, invisible until the extra is installed | I1 probes **both** before anything depends on them; the fix, if needed, names that exact warning — never a blanket ignore |
| the committed PDFs drift from their generator | a byte diff nobody runs | `make corpus` is a gate in `check.sh`, not an instruction — byte-exact for the sixteen text-layer fixtures, within a stated pixel tolerance for the three rasters, because a raster gate that demands bit-exactness fails on the next renderer bump instead of on a real change |
| quality thresholds are chosen from the same corpus they score | v0.1 shipped precisely this for confidence and had to label the result a floor | the corpus is *ground-truth-labelled*, so the metrics are measurements; only the thresholds come from it, and the report header says so |
| a `schema_version` bump strands users who will never index a PDF | a forced rebuild is a machinery cost with no feature benefit to them | announced in the CHANGELOG and in the error's remedy; rebuilds are free and `ledger.jsonl` survives |
| pdfium builds, or the layout algorithm, change extraction silently | every stored span would be stale with nothing saying so | the free backend's fingerprint includes the pypdfium2 and pdfium versions, `LAYOUT_VERSION` **and** the fitted running-head threshold, so any of them changing is a cache miss **and** a per-document coherence refusal; the paid backend hashes the pdfium versions too, because it slices and audits with them |
| a PDF-shaped file that is not a PDF, or a 400 MB PDF, hangs sync | resource behaviour, not parsing behaviour | I3b's reader is the only free I/O boundary; a corrupt-header fixture, an encrypted fixture and a size guard with a stated limit are tested there by name; the paid path re-checks the 32 MB / 600-page API limits before encoding |
| CI time grows from a three-leg matrix | build machinery, felt every PR | 19 tiny synthetic files under a 2 MB budget, no model weights, no API key; the `[light,pdf,claude]` leg installs one pure-Python SDK and never calls it; the matrix legs skip the `model`-marked tests, which keep running exactly where they run today — the dedicated `check` step with the `st` extra, unchanged by this release |
