**Status:** draft — not yet reviewed · **Date:** 20260727 15:21
**Source of truth:** [`docs/DESIGN.md`](../docs/DESIGN.md) (pass 7). This plan sequences §8's v0.2
row — and amends §8, because the decisions below take v0.2 past what that row says. Every amendment

**Written against** [`v0.1.md`](v0.1.md)'s close-out ("What the build taught", twelve rules) and the

**Baseline:** v0.1.3, `main`, clean. `schema_version` 1, extras `st` and `light`.

## Goal

A PDF dropped into `docs/` is indexed, chunked, retrievable and citable by page — and the quality of
the text that made it in is **measured, not assumed**. DESIGN §9 calls PDF extraction *"the most
likely source of silent quality loss"*; the release exists to make that loss visible before it
reaches a user's answers.

v0.2 ships **two** extractors: a free, local, offline default (`pypdfium2`) and an **opt-in paid
Claude-vision extractor** that puts scanned PDFs in scope for the first time. Because a paid path
exists, v0.2 also ships **the whole budget machinery**: §5 says the budget system ships in the same
release as the first thing that can spend, "which is the honest ordering", and that first thing is now
the extractor rather than `pnk ask --deep`. Not scope creep — the design's own rule applied to the
user's decision. Every increment ends **green** (`./check.sh`, equivalently `make check`) and
**committed on its own**, so any regression bisects to one increment.

**Checked dead end — do not re-litigate.** Claude's **citations API** was investigated as a source of
exact character offsets and ruled out. Verified in the Anthropic API reference: a PDF `document` block
returns **`page_location`** (`start_page_number` / `end_page_number`, 1-indexed) — **`char_location` is
returned only for plain-text documents**. Citations are also a paid, query-time call and are
**incompatible with `output_config.format`** (400), the mechanism I7 uses to validate extraction. So
they cannot supply the offsets, cannot be free, and cannot coexist with the extractor. Decision 4 stands.

## Ground rules (apply to every increment)

- **The gate is an artifact, not a list of commands** (rule 1): `./check.sh` / `make check` passes
  immediately before `git commit`, and every new gate is **added to that script**, never described in
  prose. Two v0.1 commits landed red because the gate was a shell pipeline. New gates and owners:
  extras-not-core (I1), corpus-regenerates (I2), `pdf-eval` baseline (I3b), price-table
  well-formedness (I6a), paid-path allowlist (I7).
- **Worktree + branch per increment**, `YYYYMMDD_HHMM-i<N>-<slug>` per CLAUDE.md.
- **No inline type suppressions at all** (rule 7). Both that existed in v0.1 hid real defects; the
  Anthropic SDK's response unions are the temptation here, so narrow with an explicit
  `block.type == "text"` check, never a cast.
- **Test-machinery rules, beside the algorithm rules** (rule 5): a fake must not derive its answer
  from the input under test, so **the fixture generator is not the extractor** and each fixture's
  ground truth is authored from its *spec*; a stand-in must be adversarial in the dimension it stands
  in for, so the registered `fake` extractor returns deliberately ugly text (double spaces, a stray
  running head, a hyphen join) and the **recorded** paid-API fixtures include a refusal, a
  schema-invalid page and a page that drops content; no `or` in an equality assertion; a skip condition
  must check **every half** of its environment claim — `pdf` checks the extra imports **and** the
  fixture exists, `paid` checks `anthropic` imports **and** a key is present **and**
  `PINAKES_ALLOW_SPEND=1` is set, so no test spends without all three.
- **Test-environment configuration lands in I1** (rule 6): both markers and their multi-part
  predicates, `SOURCE_DATE_EPOCH` pinning for fixture generation, and a probe that pypdfium2's import
  is silent under `filterwarnings = ["error"]`. All plan-time decisions; v0.1 paid for deciding its
  equivalents at I10.
- **Retrospectives are an input, not only an output** (rule 10): re-read `docs/RETROSPECTIVES.md` at
  the *start* of each increment, and land findings and fixes as their **own commit** — v0.1 lost that
  in 5 of 15 increments, and bisectability depends on it.
- Docs rule (CLAUDE.md): a user-facing surface added in an increment updates `docs/DESIGN.md`, the
  README and `--help` **in the same commit**; every date carries `HH:MM`; the CHANGELOG `[Unreleased]`
  line lands with the code, and `[0.2.0]` is cut by I9.
- **CI never spends money.** No CI job holds an API key; the paid path is exercised end to end from
  committed recorded responses. Real-API runs are human-gated (rule 9), with date, model and cost
  recorded.
- **v0.2 must not move the demo KB's eval numbers.** If `make eval` shifts, that is a defect to
  explain, not a tuning opportunity (CLAUDE.md's retrieval rule).

## Prior art: PDFScout

[PDFScout](https://github.com/lucagattoni/PDFScout) (the user's own project, MIT) is a LangGraph
multi-agent PDF extractor on Claude's native PDF vision. I7 is written against it deliberately, and
says so in its module docstring.

**Borrowed.** (a) **The completeness audit against the PDF's own embedded text layer** — PDFScout's
`coverage_node` compares significant words (alphabetic, ≥5 chars, NFKC-folded, order-free) from the
native layer against the model's per-page output and re-extracts pages that dropped or duplicated
content. Here it is *free*, because pypdfium2 already produced that layer in I3b, so it is the paid
path's quality gate at zero marginal cost. It brings PDFScout's own caveat too, which becomes a risk
row: a scanned page has **no usable native layer**, so the audit is blind on exactly the pages the paid
path exists for, and the corpus's hand-authored ground truth is what covers those. (b) **Per-page
schema validation with bounded retries** (≤3), so a malformed page is re-asked rather than silently
truncating the document. (c) **Provider-side prompt caching** — PDFScout reports pages 2–N at ~10% of
input cost. (d) **Local pre-checks before any API cost** — page count and encryption detection, offline.

**Rejected.** *LangGraph and the multi-agent graph* — pinakes has one extraction task, and a graph
framework is exactly the "second, worse agent framework" §9 names as a risk. *The classifier and
hierarchy agents* — they produce a document tree; pinakes needs linear text with page spans, and a
hierarchy would be a second structure with no consumer (v0.1's I6 is the record of what an unused
structured column costs). *SQLite checkpoint/resume* — resume uses per-page staging files inside the
extraction cache instead (I7), rather than a second durability surface beside the cache and
per-document transactions that already exist. *Per-page parallel fan-out, in v0.2* — the hard cap is a
**running** reservation total (§5) and concurrent calls can breach it between reservation and
reconciliation; parallelism lands in v0.3 once the accountant has a ledger to prove itself against.

## What this plan deliberately does NOT decide

- **Table structure recovery.** The table stratum measures whether a table's text survives in readable
  order with label/value adjacency intact — not whether a grid is reconstructed as a grid.
- **PDF outlines/bookmarks as a `heading_path` substitute.** Pages are the unit v0.2 ships.
- **The Files API** (`files-api-2025-04-14`) instead of base64 document blocks. It uploads once and
  references a `file_id` across requests, but needs the beta header on **both** the upload and the
  message call plus an upload lifecycle to clean up. **Default: base64 + prompt caching** — same cost
  profile, no extra lifecycle. Revisit if a corpus routinely re-extracts the same document.
- **Figures, embedded images, captioning** beyond what the paid extractor's page output already says;
  Office, HTML, email, chat (§1 rules them out); any change to chunking parameters, fusion, reranking
  or the confidence signal; `pnk link` and cross-KB traversal (v0.3); `sqlite-vec` (v0.5).
- **`pnk ask --deep`** — still v0.4; v0.2 ships the budget machinery it will use, not the loop.
  **Default:** the accountant's "operation" for v0.2 is one `pnk sync` invocation.

### I1 — Extras, the extractor seam, and an honest core-only failure

`pyproject.toml` gains `pdf = ["pypdfium2>=5.12"]` and `claude = ["anthropic>=0.116"]` under
`[project.optional-dependencies]`. `src/pinakes/extract/` becomes a package: `__init__.py` holds an
`Extractor` protocol (`extract(path) -> RawPages`), the frozen `RawPages` / `Page` / `Block` types, and
an **open module-level registry keyed on backend name with lazy imports** — the single best structural
call of v0.1 (I7), and what lets the real CLI be driven end to end with neither extra installed.
`errors.py` gains `ExtractorMissingError` (names the extra) and `ExtractionError`, both routed through
the existing `_rebuild` helper so they survive pickling (v0.1 I1/I4). `chunk.source_type` maps `.pdf` →
`"pdf"`. `sync._index_document` **routes on `source_type`** instead of unconditionally calling
`read_text(encoding="utf-8")`; a PDF today raises `UnicodeDecodeError` and is logged as an opaque
`index`-stage failure. The manifest gains `[extraction] backend = "pypdfium2"`, validated against the
registry — an unknown value is an error. `pnk doctor` gains a `pdf extractor` check: OK when
importable, WARN naming the extra when `include` can match `*.pdf`. Test-environment configuration per
rule 6, listed in the ground rules.
**Tests:** registry dispatch and a monkeypatched import failure raising `ExtractorMissingError` naming
`pinakes[pdf]`, no uninstall needed (`tests/test_extract.py`); the extended `source_type` table
(`tests/test_chunk.py`); a KB with one PDF and no extractor recording a `failures` row at stage
`extract`, indexing the other N−1 documents, exiting non-zero and printing the remedy **once** rather
than per document (`tests/test_sync.py`); an unknown `backend` rejected (`tests/test_manifest.py`).
**Exit criteria (repo-verifiable):** `./check.sh` green under `--extra light` and under
`--extra light --extra pdf`; a new `check.sh` gate fails if `pypdfium2` or `anthropic` appears in
`[project.dependencies]`; `pnk doctor` prints the new check in both install states.

### I2 — The synthetic hard-case PDF corpus and its generator

`tests/pdf-corpus/`: a committed generator, the committed PDFs it produces, and one hand-authored
`<name>.expected.txt` per fixture. **No real-world PDF is ever committed** (CLAUDE.md: the repo is the
engine). Ground truth comes from the generator's *spec*, never from extractor output — otherwise the
test asserts only that the extractor agrees with itself. Sized **per stratum, not in aggregate**
(rule 4 — v0.1 sized its golden set at ≥40 in aggregate and still ended with an 8-question no-answer
stratum it had to label a floor):

| Stratum | n | Must contain |
|---|---|---|
| two-column | 3 | reading order across a gutter; a caption straddling both columns; a left column ending mid-sentence |
| tables | 3 | a bordered grid; a borderless whitespace-aligned table; one with a spanning header cell |
| headers / footers | 3 | a repeating running head; page numbers; a footer present only on page 1 |
| ligatures & hyphenation | 3 | U+FB01/U+FB02; a soft hyphen; a word split across a line break **and** one across a page break |
| **scanned / image-only** | 3 | a page rastered from known glyph coordinates with **no text layer**: clean, skewed 2°, low-contrast. This is the stratum the paid path exists for |
| pathological | 2 | a text layer in invisible render mode; a truncated/corrupt-header file |
| baseline | 2 | plain single-column prose, one page and twelve pages |

Nineteen documents, ≥45 pages, under a stated byte budget. The generator writes raw content streams, no
layout engine: the fixtures are not documents, they are **text layers with known coordinates**, and a
layout engine would hide the variable under test behind its own decisions. The scanned stratum rasters
those same coordinates, so its ground truth is identical to its text-layer twin — which makes
free-vs-paid directly comparable on the same content.
**Tests:** `tests/test_pdf_corpus.py` — regeneration is byte-identical to what is committed (fixed
producer string, `CreationDate`/`ModDate` from `SOURCE_DATE_EPOCH`); every fixture has a ground truth
and every ground truth a fixture; stratum counts match the table, so the corpus cannot silently shrink.
**Exit criteria (repo-verifiable):** `make corpus` leaves no diff, and that check is a gate in
`check.sh`. **Not** an exit criterion: any claim about extraction quality — nothing extracts yet.

### I3a — Extraction core, pure (rule 11: the pure half)

`extract/layout.py`, operating only on the I1 types — no PDF library, no filesystem:

- `reading_order(page)` — column detection by x-gap clustering, then top-to-bottom within a column.
- `strip_running_heads(pages)` — a line recurring in the same y-band on ≥ *T* of pages, digits
  normalised, is a running head. **The threshold ships with its denominator**: the result reports
  `suppressed N of M pages`, so a wrong *T* is visible instead of silently eating a real heading.
- `join_hyphenation(lines)` — join a trailing hyphen or U+00AD when the continuation starts lowercase;
  never join across a heading or a suppressed running head.
- `normalise(text)` — ligature expansion (U+FB00–U+FB06), NFC, an explicit whitespace policy.
- `assemble(pages) -> ExtractedText(text, page_spans)` — **offsets are emitted with the text, never
  accumulated afterwards** (v0.1 I6: spans from `match.start()` rather than a running total are exact
  by construction rather than by accounting).

**Tests:** `tests/test_extract_layout.py`, table-driven — one case per rule, plus the compound cases a
table cannot express: a two-column page continuing mid-sentence into the right column; a running head
that is a genuine heading on exactly one page; a hyphenated word split across a page break where the
next page opens with a running head. Two property assertions over **every** case:
`"".join(text[s:e] for s, e in page_spans) == text`, and `page_spans` contiguously covers
`[0, len(text))`.
**Exit criteria (repo-verifiable):** one named test per rule and per compound case; both properties
hold across all of them; an import-graph test asserts `layout.py` imports no PDF library.

### I3b — The pypdfium2 adapter and the quality metrics (rule 11: the I/O half)

`extract/pdfium.py` turns a file into `RawPages`. pdfium's text API is character-level, so this module
owns assembling characters into the `Block` model I3a consumes — which is why **review effort is
budgeted here, not at the algorithm** (rule 11's corollary: v0.1's pure half produced one finding and
the I/O half four, all environmental). Its option set is **pinned and hashed** into the
`extraction_fingerprint` — `sha256(backend name, pypdfium2 version, pdfium build, option dict)`,
truncated — written to `meta` at sync and into the I4 cache key.

`extract/quality.py` scores an extraction against a ground truth. **Every rate ships with its
denominator as a co-metric** (rule 3 — v0.1's `false_abstain: 0.0` was vacuous and would have passed a
CI gate forever):

| Metric | Numerator | Denominator |
|---|---|---|
| `char_recall` | expected non-space characters found, in order | expected non-space characters |
| `order_fidelity` | LCS length over word sequences | expected word count |
| `junk_rate` | extracted words absent from the ground truth | extracted word count |
| `pair_adjacency` | asserted (label, value) pairs within *N* characters | asserted pairs |
| `word_coverage` | significant native-layer words present in the extraction | significant native-layer words |
| coverage | `documents_scored`, `pages_scored` | `documents_total`, `pages_total` |

`word_coverage` is the PDFScout completeness audit, defined here as a pure function of two strings so
it can be tested against hand-computed answers; I7 consumes it as the paid path's re-extraction
trigger, and a metric that can be wrong on a known input is not fit to gate anything.
`python -m pinakes.extract.quality tests/pdf-corpus` writes a JSON report; `--baseline` compares **per
stratum** with a tolerance, mirroring `eval.compare`; `make pdf-eval` wraps it and joins `check.sh`.
The scanned stratum's expected free-path `char_recall` is **0.0** — a declared zero with its fixtures
named, not a passing score.
**Tests:** `tests/test_extract_quality.py` — each metric on hand-built strings with hand-computed
answers; `documents_scored == documents_total` for every stratum; a planted regression (one fixture's
extraction truncated to its first page) **fails** the baseline comparison.
**Exit criteria (repo-verifiable):** `make pdf-eval` green against a committed
`tests/pdf-corpus/baseline.json`; the planted-regression test passes by failing the comparison; every
stratum's denominators are non-zero.

### I4 — The extraction cache

`extract/cache.py`. One JSON per entry — `{schema, content_hash, fingerprint, page_count, page_spans,
text}` — because a text/JSON pair introduces a half-written-pair corruption class that need not exist.
Written to a sibling temp and `os.replace`d. Invalidation is **by key, never by mutation**: an edited
PDF or an upgraded extractor simply misses.

```text
.pinakes/
├── index.db          ← disposable, rebuilt
├── ledger.jsonl      ← NEVER touched (§6.3)
└── cache/extract/
    ├── <content_hash>-<fingerprint>.json      ← a complete extraction
    └── partial/<content_hash>-<fingerprint>/  ← per-page staging, written only by I7
```

Eviction: after a **fully successful** sync, entries whose `content_hash` matches no active document
are removed — never after a run that recorded failures, never during `--sidecars-only`, never during
`--rebuild` before the swap succeeds. `pnk sync --clear-cache` (named in §6.3, never implemented)
empties `cache/` only; `--rebuild` leaves it alone, which is the whole point of a cache. `pnk doctor`
reports entry count, bytes, and `orphans / entries`.
**Tests:** `tests/test_extract_cache.py` — a second sync of an unchanged PDF calls the adapter **zero**
times (spy-counted); a changed document, a changed fingerprint and a truncated cache file each miss
rather than crash; two KBs holding the same PDF get two cache files. Plus
`tests/test_sync.py::test_clear_cache_preserves_the_ledger`.
**Exit criteria (repo-verifiable):** the zero-call assertion; the ledger-survives assertion;
`--clear-cache` in `pnk sync --help` and in §6.3's prose in the same commit.

### I5 — PDF chunking, page provenance, and the span invariant (`schema_version` 2)

`chunk_document(kind="pdf")` consumes the extraction's blocks, split at page boundaries so a chunk
never spans two pages without recording both. The existing `_fit` / `_atomise` machinery is reused
unchanged — and its guarantees are **re-asserted for the new path, not assumed**: the token limit,
never-trim, and the overlap-must-not-breach-`max_tokens` rule that v0.1's I6 found broken. `store.py`:
`chunks.page_start` / `page_end` (INTEGER, NULL for non-paged sources), `ChunkRow` and `Chunk.as_row()`
grown together (already coupled), `SCHEMA_VERSION = 2`. `heading_path` stays **NULL** for PDFs — a PDF
has pages, not headings, and stuffing `"p. 7"` into a free-text filter/citation column is v0.1's I6
defect rewritten. `meta` gains `extraction_fingerprint`; §4.4's coherence gate refuses a query when the
index's fingerprint differs from the installed extractor's, same remedy shape as a model mismatch.
**Tests:** `tests/test_chunk_pdf.py` — **the span invariant over all 19 fixtures and every chunk**
(`chunk.text == extracted.text[char_start:char_end]`); every character of the extraction lands in ≥1
chunk (v0.1's never-drop guarantee, re-proved here); page numbers monotonic and within `1..page_count`;
a two-page chunk recording both; `heading_path is None` for every PDF chunk. `tests/test_store.py` —
schema version 2, and a version-1 index refusing to open naming `pnk sync --rebuild`.
**Exit criteria (repo-verifiable):** the invariant holds corpus-wide; `SCHEMA_VERSION == 2`; a v0.1
index raises `IndexSchemaError` with the rebuild remedy; the CHANGELOG entry states the forced rebuild
in the same commit.

### I6a — Budget core, pure (rule 11: the pure half of the money machinery)

`src/pinakes/budget/`, with **no I/O and no `anthropic` import**. `prices.toml` ships in the wheel like
the templates, carrying `as_of` as `YYYYMMDD HH:MM`, per-model `input_per_mtok_usd` /
`output_per_mtok_usd`, the cache-write (1.25×) and cache-read (0.10×) multipliers, and — because the
manifest prices in EUR and the vendor in USD — a `usd_per_eur` rate carrying the **same** `as_of`.
Seeded from the current table: `claude-opus-5` at $5.00 / $25.00 per MTok. `estimate.py` is a pure
function from (page count, page kind, model, cache plan) to tokens and cost, shipping its denominator
as `pages_estimated N of M`; its per-page token constant is **measured**, not guessed, with
`measured_on` recorded beside it — until that measurement (human-gated, I7) it uses a documented
conservative ceiling derived from the API's own per-request limits. `reserve.py` is the §5 accountant:
before each call it reserves **worst case** = (estimated input tokens + the request's output-token
bound) × price, and if `spent + reserved > per_operation_eur` the call is **never made**;
reconciliation folds the response's true usage back in. An "operation" is one user-facing invocation —
for v0.2, one `pnk sync`. `window.py` aggregates by day/month in `[budget] timezone`. `[budget]` gains
`max_price_age_days` (default 30): an estimate against older prices is refused, not silently wrong.
**Tests:** `tests/test_budget_core.py`, table-driven — the exact cap boundary (`spent + reserved ==
cap` proceeds; one cent more does not); a reservation **never below** the reconciled actual across
every recorded fixture in I7's set; confirm threshold and hard cap staying independent, so confirming
at the cap value is reachable (DESIGN pass 3's finding); window boundaries across a DST transition in a
non-UTC timezone; a stale `as_of` refusing to estimate and naming the remedy; a malformed
`prices.toml` as a startup error, not a silent zero.
**Exit criteria (repo-verifiable):** the boundary tests; an import-graph test asserting `budget/`
imports neither `anthropic` nor anything under `extract/`; a `check.sh` gate parsing `prices.toml` and
failing if `as_of` is missing or unparseable. **Deliberately not a CI gate:** price *staleness* — a
wall-clock gate fails the build on a quiet weekend with no code change, so staleness is a `pnk doctor`
WARN and a runtime refusal, where it protects a user instead.

### I6b — Budget I/O: the ledger, the prompt, `pnk budget` (rule 11: the I/O half)

`budget/ledger.py` appends to `.pinakes/ledger.jsonl`; each line is a single sub-4KB `O_APPEND` write,
atomic on POSIX (§5). **The ledger stores no query text and no document content** — timestamp,
operation id, operation kind, model, token counts, cost, KB id, nothing more — and a test asserts it by
running a paid extraction from a recorded fixture whose page text contains a unique sentinel and
grepping the whole ledger for it. Two lines per call keyed by one operation ULID: a **reservation**
written *before* the call and a **reconciliation** *after*. That is the durability answer (rule 12) — a
crash between the call and the ledger write would otherwise lose spend history permanently, the one
thing in `.pinakes/` that cannot be recomputed — and a reservation with no reconciliation is reported
as `unknown outcome`, not dropped and not counted as zero. `confirm_above_eur` prompts on a TTY; **with
no TTY and no explicit `--yes` the run aborts**, never proceeds silently, and `--yes` (required for
cron) says in `--help` what it authorises. `pnk budget` shows spend by day/month/operation with
`reservations N, reconciled M, unknown K`; `pnk doctor` gains a price-table check: OK, or WARN past
`max_price_age_days` naming the file.
**Tests:** `tests/test_ledger.py` — the sentinel test; a process killed between reservation and
reconciliation leaving a readable ledger and an `unknown outcome` row; concurrent appends from two
processes interleaving no record; `--rebuild` and `--clear-cache` both leaving the ledger
byte-identical. `tests/test_cli_budget.py` — `pnk budget` on an empty ledger printing zeros rather than
a traceback; totals on a mixed ledger matching a hand-computed fixture; no-TTY without `--yes` exiting
non-zero with a remedy.
**Exit criteria (repo-verifiable):** all of the above; §5 amended to say the machinery ships in v0.2,
and §8's v0.4 row updated in the same commit.

### I7 — The paid Claude-vision extractor, the allowlist gate, the invariant amendment

`src/pinakes/extract/claude.py` — **the only module in `src/` permitted to import `anthropic`.**
Registered as backend `claude-vision`, reached only when the manifest says so or `pnk sync
--extract=claude-vision` is passed. Every free step precedes every paid one:

1. **Local pre-checks, zero cost** (PDFScout): page count, encryption detection, request size against
   the documented limits (32 MB per request; 600 pages, 100 for 200k-context models), and the free
   extractor's own text yield — if the free path already clears the I8 floor, the paid path **refuses
   to spend** unless `--force`, and says so. Paying to re-extract a healthy PDF is the most likely way
   a user loses money by accident.
2. **Estimate and reserve** through I6a: prompt above `confirm_above_eur`, abort above
   `per_operation_eur`, and never make the call if the reservation would breach the cap.
3. **Request shape.** A `document` content block placed **before** the text block —
   `{"type": "document", "source": {"type": "base64", "media_type": "application/pdf", "data": …}}`,
   newline-free base64, no beta header — carrying `cache_control: {"type": "ephemeral"}` so pages 2..N
   read it at ~0.1× input cost. The minimum cacheable prefix is 512 tokens on `claude-opus-5`, so a
   very small PDF will not cache: a cost fact the report states, not a failure. Structured output via
   `output_config: {"format": {"type": "json_schema", "schema": …}}` — the current parameter, not the
   deprecated top-level `output_format`, and the reason citations are unavailable (they 400 together).
   Model defaults to `claude-opus-5` via `client.messages.create`. An exact-input-token refinement may
   call `client.messages.count_tokens` *inside this module* to tighten the reservation immediately
   before the call; it is never required, because the estimate must exist on an install with no client.
4. **Per-page validation with ≤3 retries** (PDFScout). `stop_reason == "refusal"` is checked **before
   reading `content`** and counts as a page failure, retried once, then recorded.
5. **Completeness audit** via I3b's `word_coverage` against pypdfium2's native layer. Pages below the
   floor are re-extracted once, and that re-extraction is itself reserved and ledgered. Pages with no
   usable native layer (the scanned stratum) are **exempt and reported as exempt**, with their
   denominator: `audited N of M, exempt K of M`.
6. **Staging and commit.** Each validated page is written to
   `cache/extract/partial/<hash>-<fingerprint>/<page>.json` (temp + `os.replace`) as it completes, so
   an interrupted 200-page run does not re-pay for pages already extracted. Only when every page passes
   is the single complete cache entry written and the staging directory removed. A partially extracted
   document writes **no** complete entry and goes to `failures`; `on_exceed = "partial"` is honoured at
   the corpus level (completed documents keep their entries, the run stops cleanly), never at the page
   level — a half-extracted document in the index is the silent truncation §4.6 exists to prevent.

**The CI free-path gate becomes an allowlist.** Today `.github/workflows/ci.yml` fails if `anthropic`
is imported anywhere under `src/`. Precisely, the new gate: one file, `.paid-path-allowlist` at the
repo root, lists the permitted paths — exactly `src/pinakes/extract/claude.py` at v0.2 — and
**`check.sh`, CI and the test all read that one file**, so three copies cannot drift. **Gate 1:** every
listed path must exist, so a stale entry cannot rot unnoticed. **Gate 2:** the paid-client grep
(`anthropic|openai|cohere|mistralai|google\.generativeai`) runs over `src/` **excluding** the listed
paths; any hit is a hard failure with the existing error message. **Gate 3:** `anthropic` must not
appear in `[project.dependencies]` (I1's gate, reused). **Gate 4, the one that actually matters,** is a
test rather than a grep: after a full free-path run (`pnk sync`, `pnk search`, an MCP handshake),
`"anthropic" not in sys.modules`. Lazy registry imports make this provable, and it catches the
transitive import a grep never would.

**CLAUDE.md is amended in this increment.** "No code path may make a paid API call outside `pnk ask
--deep`" becomes an enumerated allowlist:

> **Paid entry points are an enumerated allowlist.** Exactly these may spend: `pnk sync` with
> `[extraction] backend = "claude-vision"` or `--extract=claude-vision`; `pnk ask --deep` (v0.4). Each
> goes through the §5 accountant. Adding an entry point edits this list, `.paid-path-allowlist` and
> DESIGN §1 in the same commit.

**Tests:** `tests/test_extract_claude.py`, driven entirely by **committed recorded responses** (of the
synthetic corpus only — no real content ever enters this repo): a happy multi-page extraction; a
schema-invalid page retried and recovered; a page that exhausts retries; a `stop_reason == "refusal"`
handled before `content` is touched; a page failing the audit and re-extracted; an interrupted run
resumed from staging with **zero** re-calls for staged pages (spy-counted); a reservation that would
breach the cap so the call is never made (spy asserts zero calls); a `--force`-less refusal on a PDF
whose free text yield is healthy. Plus `tests/test_paid_path.py` —
`test_the_free_path_never_imports_the_paid_client`, `test_the_allowlist_matches_the_source_tree`.
**Exit criteria (repo-verifiable):** the whole paid suite green with `anthropic` **not installed** (the
recorded-fixture driver stands in for the client through the registry); the four gates in `check.sh`
and CI; CLAUDE.md, DESIGN §1, §8 and §9 amended in this commit.
**Exit criteria (human-gated — these gate nothing in the repo)** (rule 9): one real-API run over the

### I8 — `pnk doctor` text yield, `path:page` citations, and the trace passes

`pnk doctor` gains a `text yield` check over PDF documents: non-whitespace characters per page,
reported as `median C chars/page over N of M PDF documents`, listing by path any document below the
floor. The floor is **fitted on the I2 corpus and justified by it** — the scanned fixtures are the
positive control at zero, the twelve-page baseline the negative control — never chosen by intuition,
and its remedy now names the paid path and its cost rather than "out of scope". `pnk search` renders
`path:page` in citations; `--json` carries `page_start`/`page_end`.

**Trace one datum end to end** (rule 2 — the two most expensive plannable misses in v0.1 were both
producer/consumer *name* agreement with *column* disagreement, and five consistency passes could not
see them). Three tests in `tests/test_pdf_trace.py`:

1. `test_a_table_cell_word_survives_every_hop` — one word from a value cell of the bordered-table
   fixture, five hops, each asserting against the value carried from the previous one: **extraction**
   (the word is in `ExtractedText.text` at offset `o`, page `p`) → **cache** (the cached JSON for that
   content hash yields the same `o` and `p`) → **chunk** (exactly one chunk has
   `char_start <= o < char_end`, its text contains the word, its `page_start == p`) → **FTS**
   (`SELECT rowid FROM chunks_fts WHERE chunks_fts MATCH …` returns that chunk's rowid) → **search**
   (`pnk search` returns that passage with `path:p` in the rendered citation).
2. `test_every_filter_column_is_populated_for_pdfs` — every filter dimension a PDF can be selected by
   (`source_type`, `path_prefix`, `mtime`, `tags`) resolves to a column **non-null for every PDF row**,
   asserted by a query, not by reading.
3. `test_a_paid_page_traces_from_estimate_to_the_budget_report` — the money equivalent, and the reason
   the risk table aims at machinery: one page's cost from **estimate** → **reservation line** → the
   recorded response's **`usage`** → **reconciliation line** → the total `pnk budget` prints. Each hop
   asserts against the previous one's number, so a unit slip (tokens vs MTok, USD vs EUR) cannot hide
   in an intermediate layer.

**Exit criteria (repo-verifiable):** all three trace tests pass; the doctor check WARNs on the scanned
fixtures and is OK on the baseline; `--help` and README show the new citation format.

## Durability sweep (rule 12)

*Which writes lose unrecoverable information if interrupted?*

- **`ledger.jsonl` — the only genuinely unrecoverable write, and it is new.** A crash between the API
  returning and the ledger append loses spend history permanently: money left the account and nothing
  records it. Answered by I6b's two-line reservation/reconciliation protocol — a torn write degrades to
  a *visible* `unknown outcome`, never to a silent zero.
- **Paid staging entries — recoverable, but only at cost.** Regenerable in principle, and that
  regeneration is exactly what the user is paying for; written per page, atomically, consumed on resume
  (I7). Without them an interrupted 200-page run re-pays for everything.
- **Free cache entries — recoverable and free.** Still atomic: a half-written JSON that happens to parse
  is worse than a miss. **The eviction sweep** is the only new delete — derived state only, only after a
  fully successful sync, guarded and tested (I4).
- **Sidecars for PDFs — unchanged and already atomic** (v0.1 I5, rename-based). Re-asserted rather than
  assumed: the ULID a sidecar carries is still the one thing no later command can recompute.
- **The `-wal`/`-shm` lesson (v0.1 I8b) transfers:** cache and staging are *sets* of files under
  directories, so `--clear-cache` and the sweep are tested by listing the directory afterwards, never by
  trusting that one `unlink` was enough.

## Risks specific to this sequencing

Aimed at **machinery**, deliberately: v0.1's risk table enumerated algorithmic risk, and all seven of
its HIGH findings came from areas it never contemplated — durability, file naming, boundary arithmetic,
vacuous metrics, and the gate itself.

| Risk | Why it is machinery | Mitigation |
|---|---|---|
| **Unbounded spend.** A loop, a retry storm, or a 600-page corpus turns an opt-in into a bill | the cap is arithmetic across a *running* total, and the failure is silent until the invoice | pre-call reservation refuses the call (I6a boundary test); one operation = one `pnk sync`; sequential pages, so no concurrent call can breach the window between reserve and reconcile; no-TTY aborts without `--yes`; the free path is checked first and refuses to pay for a healthy PDF |
| **The cache key is right and the cache *path* is wrong** | the I8b shape: correlated filenames, correctness argued about one of them | the cache lives under each KB's own `.pinakes/`; a test syncs two KBs holding the same PDF and asserts two files; staging is keyed by the same pair plus page |
| **Partial or interrupted extraction leaves a document half in the index** | a truncated document is exactly the silent quality loss §4.6 exists to prevent, and nothing in the output reveals it | all-or-nothing commit: no complete cache entry until every page passes, and the document goes to `failures`; `on_exceed = "partial"` is corpus-level only, stated in `--help` and §5 |
| **The paid-path allowlist erodes** | a one-line import in a new module quietly makes the free path paid, and greps drift from the code they guard | one `.paid-path-allowlist` read by `check.sh`, CI and the test; the decisive check is behavioural (`"anthropic" not in sys.modules` after a free run), not textual; adding an entry point must edit CLAUDE.md and DESIGN §1 in the same commit |
| **Scanned-PDF quality cannot be measured by the audit that measures everything else** | the completeness audit's witness is the native text layer, and a scanned page has none — the gate is blind on precisely the stratum the feature exists for | the audit reports `exempt K of M` rather than scoring exempt pages as passing; the scanned stratum's ground truth is hand-authored from the generator's spec; its numbers land in §9 with date, model and cost, labelled as measured on synthetic rasters |
| **Price-table staleness, and the USD→EUR rate inside it** | the manifest prices in EUR and the vendor in USD; the rate is a second number that goes stale with nothing saying so | `usd_per_eur` carries the same `as_of` as the prices; `pnk doctor` WARNs past `max_price_age_days`; an estimate against stale data refuses rather than guessing; the reservation is worst-case, so drift errs high. Not a CI gate — see I6a |
| **The recorded-fixture harness diverges from the real API** | a fake that encodes only the happy path proves nothing about retries or refusals | fixtures include a refusal, a schema-invalid page and a page that drops content; the one human-gated real-API run at I7 is the reconciliation, and its date and model are recorded |
| pypdfium2 warns at import, and `filterwarnings = ["error"]` turns every PDF test red | a pyproject setting colliding with a dependency, invisible until the extra is installed | I1 probes it before anything depends on it; the fix, if needed, names that exact warning — never a blanket ignore |
| the committed PDFs drift from their generator | a byte diff nobody runs | `make corpus` diff is a gate in `check.sh`, not an instruction |
| quality thresholds are chosen from the same corpus they score | v0.1 shipped precisely this for confidence and had to label the result a floor | the corpus is *ground-truth-labelled*, so the metrics are measurements; only the thresholds come from it, and the report header says so |
| a `schema_version` bump strands users who will never index a PDF | a forced rebuild is a machinery cost with no feature benefit to them | announced in the CHANGELOG and in the error's remedy; rebuilds are free and `ledger.jsonl` survives |
| pdfium builds change extraction silently | every stored span would be stale with nothing saying so | the fingerprint includes the pypdfium2 and pdfium versions, so a change is a cache miss **and** a coherence refusal |
| a PDF-shaped file that is not a PDF, or a 400 MB PDF, hangs sync | resource behaviour, not parsing behaviour | I3b's adapter is the only free I/O boundary; a corrupt-header fixture and a size guard with a stated limit live there; the paid path re-checks the 32 MB / 600-page API limits before encoding |
| CI time grows from the `[light,pdf]` matrix | build machinery, felt every PR | 19 tiny synthetic files, no model weights, no API key; the matrix job skips the model-marked tests |
